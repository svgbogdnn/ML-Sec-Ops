подробно о двух

CVE-2021-39201 - wordpress

wordpress это cms для сайтов и блогов редактор в нем нужен чтобы создавать и редактировать страницы пользователь вводит текст вставляет блоки и публикует материал проблема была в том что роль без права unfiltered_html все равно могла вставить скрипт через редактор

последствия - выполнение js в браузере кража куки действия от имени пользователя

CVE-2021-40926 - getid3

getid3 это php библиотека для разбора медиафайлов она читает метаданные из mp3 и других форматов проблема была в том что параметр showtagfiles в demo.mysqli.php выводился без очистки и туда можно было вставить html или js

последствия - выполнение js в браузере кража сессии подмена страницы

часть 2

запуск

docker pull ket9/otus-devsecops-xss
docker run -d -p 8080:80 ket9/otus-devsecops-xss:latest

открыл localhost:8080 зашел в раздел xss-1 там была форма с полем comment и кнопкой save data

ход работы

сначала просто посмотрел как работает форма комментарий вводишь нажимаешь сохранить он появляется внизу на той же странице в блоке comments

потом решил проверить фильтруется ли ввод вставил в поле такой код

<script>alert('XSS')</script>

нажал save data и страница вернула это обратно как часть html

<h2>Comments</h2><p><script>alert('XSS')</script></p><hr />

перезагрузил страницу - код никуда не делся снова показывается значит он сохранился на сервере

если открыть в обычном браузере то выполняется alert с текстом xss дополнительно посмотрел логику - комментарий пишется в /tmp/comments.txt потом читается и вставляется в страницу без всякой обработки

тип уязвимости

это хранимый xss потому что код сохраняется на сервере и выполняется каждый раз когда кто-то открывает страницу а не только один раз в ответ на запрос

почему возникает

приложение берет ввод пользователя и вставляет его в html без обработки браузер видит символы < > " ' и воспринимает их не как текст а как часть страницы из-за этого тег script выполняется

меры предотвращения

  1. не вставлять ввод пользователя в html напрямую
  2. перед выводом экранировать символы < > " ' и &
  3. в php для этого есть htmlspecialchars($comment, ENT_QUOTES, 'UTF-8')
  4. если теги в комментариях вообще не нужны - запрещать их полностью
  5. проверять ввод на стороне сервера а не только на клиенте

вывод

через поле комментария удалось выполнить xss атаку приложение сохраняет введенный код и потом вставляет его на страницу без очистки уязвимость относится к хранимому xss и позволяет выполнять произвольный js в браузере любого кто откроет страницу
