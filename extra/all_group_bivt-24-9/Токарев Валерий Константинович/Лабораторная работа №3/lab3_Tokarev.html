Отчет по лабораторной работе №3

Симуляция XSS-атаки и анализ CVE

Часть I. Анализ CVE за 2021 год

Для анализа были выбраны две уязвимости в компонентах на PHP, которые наглядно показывают проблемы с фильтрацией ввода.

1. CVE-2021-43698 — phpWhois

Библиотека phpWhois используется для получения регистрационных данных доменов. Уязвимость была найдена в демонстрационном файле, где параметр поискового запроса выводился обратно пользователю без экранирования. Это позволяло внедрить вредоносный JavaScript.

2. CVE-2021-24444 — TaxoPress

Это популярный плагин для WordPress, отвечающий за работу с тегами. Проблема заключалась в недостаточной проверке прав и очистке данных при обновлении настроек, что позволяло сохранить XSS-скрипт прямо в базе данных сайта.

Итог по статистике: Всего за 2021 год было зарегистрировано более 4000 случаев XSS. Это подтверждает, что данная проблема остается одной из самых массовых в веб-разработке.

Часть II. Практика на стенде

Работа велась с уязвимым приложением в Docker-контейнере (ket9/otus-devsecops-xss).

Ход рассуждений

Сначала я проверил форму на базовую обработку HTML. После ввода <h1>test</h1> стало ясно, что сервер никак не очищает входящий текст — заголовок отрендерился браузером.

Затем был применен классический пейлоад для проверки XSS: <script>alert('XSS')</script>. Скрипт успешно выполнился, показав модальное окно. Тот факт, что алерт появлялся и при повторном заходе на страницу, говорит о сохранении скрипта на сервере.

Тип найденной уязвимости

Найденная проблема классифицируется как Stored XSS (Хранимая XSS). Она опасна тем, что вредоносный код сохраняется на стороне сервера и атакует всех пользователей, просматривающих страницу, без необходимости присылать им специальную ссылку.

Меры предотвращения

  • Экранирование (Output Encoding): При выводе любых данных в HTML-контекст нужно заменять опасные символы на их безопасные аналоги.
  • Content Security Policy (CSP): Запрет на выполнение встроенных скриптов через заголовки безопасности.
  • Флаг HttpOnly: Ограничение доступа JavaScript к сессионным кукам для защиты от угона аккаунта.
  • Использование библиотек-санитайзеров: Обработка входных данных проверенными инструментами, которые вырезают опасные теги.
