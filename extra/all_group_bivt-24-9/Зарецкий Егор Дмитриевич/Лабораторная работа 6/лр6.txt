ЛАБОРАТОРНАЯ 6 Изучение CI/CD с точки зрения инструментов ИБ (TruffleHog)
В рамках лабораторной работы нужно было посмотреть, как в CI/CD можно использовать инструменты информационной безопасности для поиска секретов в коде. Для проверки был выбран TruffleHog.


ХОД РАБОТЫ:
1. Запуск контейнера
Команда:
docker run -it -p 8080:8080 python:buster /bin/bash

pip install truffleHog

Команда:

Секрет 1
1. Путь: .travis.yml
Строка:
+      secure:  [93mpJOLBnl6427PcVg/tVy/qB18JC7b8cKpffau+IP0pjdSt7KUfBdBY3QuJ7mrM65zRoVILzggLckaew2PlRmYQRdumyWlyRn44XiJ9KO4n6Bsufbz+ictB4ggtozpp9+I9IIUh1TmqypL9lhkX2ONM9dSHmyblYpAAgMuYSK8FYc= [0m

2. Что это и почему это секрет
Похоже на зашифрованный токен Travis CI. С большой вероятностью это Personal Access Token GitHub или другой ключ доступа для CI если такой токен попадет к злоумышленнику то он сможет выполнять действия от имени владельца делать push, менять настройки, переписывать историю репозитория и т.д
Надо отозвать старый токен. Создать новый с минимальными правами и обновить его в настройках CI/CD. После этого почистить историю Git, чтобы старое значение не осталось в коммитах.
3. Как хранить
Использовать GitHub Actions Secrets или другой защищенный раздел CI/CD. Токен должен храниться в зашифрованном виде. В репозиторий его коммитить нельзя. Нужно давать минимальные права и ограничивать срок действия.

Строки:

            "<input type=\"hidden\" name=\"matchingPassword\" value=\"password\"/>\n" +

params.put("username", "csrf-"+getWebgoatUser());

В коде прямо указаны логин и пароль. Даже если это тестовые данные, так хранить учетные записи нельзя. Если эти значения использовались в реальной среде, злоумышленник сможет войти в аккаунт.

надо почистить историю Git. Сменить пароль во всех местах, где он мог использоваться. Убрать пароль из исходного кода.

Передавать логин и пароль через переменные окружения или секреты CI/CD. Такие значения не должны попадать в коммиты.

ВЫВОД
Главный вывод такой: секреты нельзя хранить в коде, README и конфигах. 
Для CI/CD надо юзать защищенные секреты и переменные окружения 
Если секрет уже попал в гит, недостаточно просто удалить его из текущего файла нужно заменить секрет, отозвать старый доступ и очистить историю репозитория.
