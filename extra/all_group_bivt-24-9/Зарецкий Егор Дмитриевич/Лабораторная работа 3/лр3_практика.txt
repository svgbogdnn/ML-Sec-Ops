ОБЩИЕ ВЫВОДЫ:

Найденные проблемы:
  1) SQL Injection на /users/v1/{username} - Категория: API8 (Injection, OWASP API Security Top 10 2019)
  2) Неавторизованный debug endpoint /users/v1/_debug с утечкой паролей и admin-флагов - Категория: API3 (Excessive Data Exposure, 2019) + API7 (Security Misconfiguration)
  3) Слабая объектная защита чтения профилей через /users/v1/{username} - Категория: API1 (BOLA/IDOR)

Но например эскалация прав через Mass Assignment в этой сборке не сработала

Что нужно сделать чтобы учулшить систему?
  1) Для SQL Injection:
  - Плейсхолдеры
  - Полный отказ от конкатенации пользовательского ввода в запрос

  2) Для утечки debug:
  - Убрать /users/v1/_debug из прода
  - не возвращать password/hash в API

  3) Для BOLA:
  - Проверять право доступа к объекту на уровне каждой операции 
  - Использовать policy-check на владельца ресурса и роль

  4) Для общей защиты API:
  - Логирование и всякие алерты  
  - Валидация входа и различные тесты
