## CVE-2021-29625 · Adminer

Тип атаки: Reflected XSS
CVSS Score: 6.1
##### Краткое описание инструмента
Adminer - это полнофункциональный инструмент управления БД, написанный на PHP. Инструмент используется для разных реляционных и нереляционных бд: MySQL, MariaDB, SQLite, PgSQL. Инструмент разворачивается на сервере и предоставляет браузерный интерфейс для: просмотра и редактирования таблиц, выполнения SQL-запросов, импорта/экспорта дампов, управления пользователями и правами и т.д
##### Описание уязвимости:
Уязвимость XSS в Adminer версий 4.6.1–4.8.0 затрагивает пользователей MySQL, MariaDB, PgSQL и SQLite. 

doc_link -  формирует ссылку на документацию конкретной СУБД по имени таблицы/столбца.
Команда вводилась вот так:
```
https://mariadb.com/kb/en/library/[ИМЯ_ТАБЛИЦЫ]/
```

Сама уязвимость возникала в ситуации, когда вводилось некорректное, но синтаксически допустимое имя таблицы, вызывалась функция doc_link. Сама функция находилась в файле `adminer/include/editing.inc.php`, параметр таблицы вставлялся в HTML без `htmlspecialchars()`. Параметр не экранировался должным образом, что приводило к XSS на стороне клиента.
##### Исправление уязвимости:
Уязвимость исправлена в версии 4.8.1. Была добавлена одна строка: добавили htmlspecialchars() вокруг параметра в doc_link.
https://github.com/vrana/adminer/commit/4043092ec2c0de2258d60a99d0c5958637d051a7

## CVE-2021-42360 - Starter Templates

Тип атаки: Stored XSS
CVSS Score: 7.6

##### Краткое описание инструмента
PHP плагин Starter Templates от компании Brainstorm Force позволяет использовать более 280 готовых WordPress-шаблонов, которые ускоряют разработку сайтов. Плагин установлен на более чем миллионе сайтов.

##### Описание уязвимости:
На сайтах, где был установлен Elementor, пользователи с правом edit_posts могли импортировать блоки на любую страницу. Уязвимая функция `elementor_batch_process()` - это PHP-код, который принимал `$_POST['url']` без валидации и загружал с него произвольный JSON, импортируя его содержимое прямо на страницу сайта.

Функция отвечала за импорт готовых блоков из библиотеки шаблонов на страницы сайта.

Таким образом, любой зарегистрированный пользователь с минимальными правами мог напрямую вызвать этот endpoint, указав в параметре url свой сервер с заранее подготовленным JSON-файлом, содержащим произвольный JavaScript.

##### Исправление уязвимости:
Уязвимость была закрыта за 3 дня после обнаружения. 4 октября - Wordfence обнаружил, сразу выпустил правило для Premium-клиентов. 7 октября Wordfence уже публично раскрыл уязвимость.

# Часть 2

1) Заходим на http://localhost:8080/XSS-1/
2) Видим окошко комментария. Сразу возникает идея с Stored XSS.
3) Пробуем, вставляем в комментарий
```
<script>alert('test');</script>
```
4) alert срабатывает, у каждого пользователя при переходе на страницу будет высвечиваться этот alert.
5) В качестве доказательства, что скрипт выполняется в контексте браузера клиента
Попробуем вывести сессионные куки через alert
```
<script>alert(document.cookie);</script>
```
В alert видим:
```
grafana_session_expiry=1772167777
```

### Итоги:

**Тип уязвимости:** Stored XSS
**Меры предотвращения:**
Нужно экранировать специальные символы HTML, заменяя их на безопасные сущности. 
Избегать и изменять нужно символы:
1) `<` заменить на `&lt;`
2)  `>` заменить на `&gt;`
3) `"` заменить на `&quot;`
4) `'` заменить на `&#039;`
5) `&` заменить на `&amp;`

В PHP для этого используется функция `htmlspecialchars()` с флагом `ENT_QUOTES`, которая экранирует все перечисленные символы разом. Её нужно применять при каждом выводе пользовательских данных на страницу.
