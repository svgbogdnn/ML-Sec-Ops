Часть 1: CVE уязвимости

CVE-2025-20156 - Эскалация привилегий через REST API в Cisco Meeting Management

Cisco Meeting Management - это платформа для мониторинга и управления корпоративными видеоконференциями, работающими на базе Cisco Meeting Server.

Недостаток уязвимости

Уязвимость заключалась в неправильной проверке авторизации при обращении к REST API. Уязвимость позволяла отправлять атакующему запросы определенные ручки без должной проверки его прав. Авторизации не было, была лишь аутентификация.

Причина уязвимости

Авторизация была реализована только на уровне входа в систему, но не на уровне каждого отдельной ручки. Backend попросту не проверял права при обращении к административным ручкам

Патч вышел одновременно с публичным раскрытием 22 января 2025, публичной эксплуатации зафиксировано не было. Источники: 1) https://habr.com/ru/companies/tomhunter/articles/875640/ 2) https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-cmm-privesc-uy2Vf8pc 3) https://nvd.nist.gov/vuln/detail/CVE-2025-20156

CVE-2025-61757 — Oracle Identity Manager, обход аутентификации в REST WebServices

Oracle Identity Manager - это корпоративная платформа управления идентификацией и правами доступа, часть Oracle Fusion Middleware. Она централизованно управляет жизненным циклом учётных записей сотрудников: создаёт, изменяет, удаляет аккаунты, назначает роли и политики доступа по всей организации.

Недостаток уязвимости

Взлом строился из двух шагов: обход фильтра и выполнение кода 1) Обход фильтра: Если пользователь добавлял в URI метаданные-суффиксы по типу ;.wadl или ?WSDL преступник обходил фильтр аутентификации и получал доступ к скрытым API эндпойнтам 2) После получения неаутентифицированного доступа атакующий взаимодействовал с эндпойнтом проверки компиляции Groovy скриптов Сам эндопойнт не предназначался для исполнения скриптов, его можно было злоупотребить для запуска вредоносного кода в процессе компиляции через функцию обработки аннотаций Groovy.

Есть информация про эту ручку: /iam/governance/applicationmanagement/api/v1/applications/groovyscriptstatus — предназначен для проверки синтаксиса Groovy-скриптов

Причина уязвимости

Уязвимость кроется в центральном SecurityFilter приложения, который отвечает за аутентификацию всех ручек приложения. Фильтр использовал регулярные выражения и allow-list для определения, какие ручки публичны, а какие требуют аутентификации.

Источники: 1) https://socradar.io/blog/cve-2025-61757-oracle-identity-manager/ 2) https://www.darkreading.com/vulnerabilities-threats/critical-flaw-oracle-identity-manager-under-exploitation 3) https://horizon3.ai/attack-research/vulnerabilities/cve-2025-61757/

CVE-2025-10948 — MikroTik RouterOS, Buffer Overflow в REST API

MikroTik RouterOS - это операционная система для роутеров и сетевого оборудования MikroTik. Массово используется у интернет-провайдеров, в корпоративных сетях и критической инфраструктуре. В RouterOS 7 появился REST API.

Причина уязвимости:

В библиотеке libjson.so есть функция parse_json_element(), которая парсит входящий json. Проблема заключается в некорректной обработке Unicode escape-последовательностей. При встрече \u без обязательных 4 hex-цифр парсер поглощает символ \ , после парсер начинает бесконечно исказть закрывающую ", которой нет и уходит в бесконечный цикл Более подробно можно прочитать в github репозитории, посвященной этой проблеме: https://github.com/a2ure123/libjson-unicode-buffer-overflow-poc

Недостаток уязвимости:

Эндпойнт /rest/ip/address/print принимает json без нормальной валидации. Нет проверки того, что после \u идут ровно 4 валидные hex-цифры. Есть лишь грубая проверка количества оставшихся символов, но не их формата.

При этом нет ни возврата ошибки, ни сброса состояния парсера при некорректном вводе, код просто молча съедает это и едет дальше. Также в основном цикле поиска закрывающей " нет ни лимита итераций, ни проверки выхода за границы буфера.

В итоге, основая проблема - Denial of Service. Роутер крашился из за одного запроса, что выводило сетевое оборудование из строя.

Источники: 1) https://zeropath.com/blog/cve-2025-10948-mikrotik-routeros-buffer-overflow 2) https://nvd.nist.gov/vuln/detail/CVE-2025-10948 3) https://zeropath.com/blog/cve-2025-10948-mikrotik-routeros-buffer-overflow

Резюме и итоги

Описание проблемы

Находясь под своим аккаунтом, мне удалось изменить пароль другого пользователя (admin), передав чужой username в path parameter /users/v1/admin/password. Сервер проверял только наличие валидного токена, но не проверял совпадает ли username в URL с username в токене.

Тип уязвимости

API1 — Broken Object Level Authorization (BOLA/IDOR)

Меры предотвращения

1) При каждом запросе сверять username из токена с username из path parameter и если не совпадают, возвращать 403 ошибку - самый важный пункт 2) Написать интеграционные тесты
