# Часть 2

После запуска контейнера и инициализации базы данных я попробовала перебирать информацию о пользователях:  
http://localhost:8080/users/v1
Приложение вернуло список пользователей: {"users":[{"email":"mail1@mail.com","username":"name1"},{"email":"mail2@mail.com","username":"name2"},{"email":"admin@mail.com","username":"admin"}]}  
Дальше я решила попробовать посмотреть данные про конкретных пользователей: http://localhost:8080/users/v1/name1  
И сервер так же показал его данные: {"username": "name1", "email": "mail1@mail.com"}  

Аналогично посмотрела данные по другим пользователям.

Могу посмотреть данные по книгам:  http://localhost:8080/books/v1  
Выдало:  {"Books":[{"book_title":"bookTitle82","user":"name1"},{"book_title":"bookTitle98","user":"name2"},{"book_title":"bookTitle68","user":"admin"}]}  

Значит, приложение позволяет получить данные по пользователям только по значению username в URL.

Попробовала изменить email пользователя через командную строку:  
C:\Users\oksik\Documents\infobez\lab2>curl -X PUT "http://localhost:8080/users/v1/name1/email" -H "Content-Type: application/json" -d "{\"email\":\"hacker@mail.com\"}"
{ "status": "fail", "message": "Invalid token"}
C:\Users\oksik\Documents\infobez\lab2>curl http://localhost:8080/users/v1/name1
{"username": "name1", "email": "mail1@mail.com"}  

Получается, мы не можем менять данные пользователей, только смотреть их через GET

Значит это уязвимость типа BOLA, так как её недостатком является предоставление доступа к объекту только параметром запроса и не проверяется с точки зрения прав доступа (сервер не требует аутентификации и не проверяет, имеет ли клиент право просматривать информацию именно об этом пользователе). Но при этом данные защищены от изменения

Меры предотвращения:  
1. Проверять право доступа к каждому объекту при каждом запросе.
2. Не отдавать данные пользователя только на основании username из URL.
3. Требовать аутентификацию перед обращением к пользовательским данным.
4. Ограничить выдачу списка всех пользователей.
5. Реализовать контроль доступа на уровне объектов (object-level authorization).
