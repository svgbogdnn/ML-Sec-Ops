def post(self):

    email = self.get_argument('mail')

    try:
        username = username.lower()
        email = email.strip().lower()
        user = User({'username': username, 'password': password, 'email': email, 'date_joined': curtime()})

недостаток: 1) при любой ошибке пользователь видит success_create(вероятно, это успех какого-либо действия) 2) сам разработчик никогда не узнает, какая именно ошибка в коде, потому что любые исключения игнорируются 3)есть риск возможности провернуть sql-инъекцию

### Описать, как устроено управление пользовательскими сессиями в django

Django управляет сессиями через промежуточное ПО (middleware) и позволяет сохранять данные о пользователе между HTTP-запросами.

1. Сначала сессия должна быть создана. При создании сессии(когда код впервые обращается к объекту сессии) пользователь получает свой уникальный сессионный ключ session_key
2.  Далее данные сессии сериализуются и сохраняются в хранилище
3.  Браузер получает cookie c именем sessionid и значением session_key
4.  При запросе django считывает sessionid из cookie, находит данные в хранилище по этому ключу и десериализует их в объект сессии в Python
