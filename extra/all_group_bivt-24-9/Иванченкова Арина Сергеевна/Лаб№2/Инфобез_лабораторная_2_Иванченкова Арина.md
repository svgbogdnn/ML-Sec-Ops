#### 1 уязвимость - CVE-2026-24134
   https://nvd.nist.gov/vuln/detail/CVE-2026-24134

   Тип :  API1:2023 - Broken Object Level Authorization
   
   Суть недостатка: Пользователь с ролью "Посетитель" может получить доступ к черновикам контента, который был создан пользователями с ролями "Редактор", "Администратор" или "Владелец".  Пользователь может подставить id черновика, после этого сервер не проверит права доступа к черновику, а пользователь получит доступ.

   Причина: Эндпоинты проверяют только аутентификацию, но не авторизацию пользователя на уровне определённого объекта. Владелец черновика не сравнивается с текущим пользователем перед выдачей прав доступа к объекту.

#### 2 уязвимость - CVE-2025-65742
   https://nvd.nist.gov/vuln/detail/CVE-2025-65742
   Тип:  API5:2023 - Broken Function Level Authorization
   
   Суть: Эндпоинты, которые отвечают за управление учётными записями и доступ к конфиденциальной информации, не требуют аутентификации. Мошенник может получить доступ к учётной записи пользователя с помощью запроса API, не имея никакого логина.

   Причина: Проверка авторизации на уровне функций либо неправильно реализована, либо её нет. Эндпоинты, которые должны быть доступны только аутентифицированным пользователям, не защищены.

#### 3 уязвимость - CVE-2025-69014

https://nvd.nist.gov/vuln/detail/CVE-2025-69014
Тип: API7:2023 - Server Side Request Forgery

Суть: Мошенник может заставить сервер отправлять произвольные HTTP-запросы. Можно указать URL, который сервер запросит без проверок , и получить доступ к внутренним сервисам.

Причина:  Эндпоинты не проверяют URL от пользователя на валидность, прежде чем передать в функции выполнения HTTP-запросов.

# 2 часть

Итак, докер образ был скачан, запущен, возможные действия в приложении были просмотрены, база данных наполнена. Самое время искать уязвимости.

Сначала было бы неплохо посмотреть подробную информацию обо всех пользователях(если её вообще можно смотреть неавторизованными пользователям)
Используем команду 
http://localhost:8080/users/v1/_debug

В базе данных у нас всего 3 пользователя
{"users":[{"admin":false,"email":"mail1@mail.com","password":"pass1","username":"name1"},{"admin":false,"email":"mail2@mail.com","password":"pass2","username":"name2"},{"admin":true,"email":"admin@mail.com","password":"pass1","username":"admin"}]}

один из них админ

### Уязвимость 1

Описание уязвимости: 
- Тип:   API8:2023- Security Miscofiguration
-  Первое, что мы видим, - приложение возвращает пароли пользователей в открытом виде. Такого быть не должно. Данные всех пользователей у злоумышленника как на ладони. После дачи этой команды он может использовать любую учётную запись в корыстных целях.

Меры предотвращения: 
- Не возвращать пароли в ответах API даже в debug режиме
- Надо хранить пароли в зашифрованном виде
- Настроить вывод сообщений безопасности без вывода конфиденциальных данных

### Уязвимость 2

Описание уязвимости:
- Тип:   API5:2023-Broken Function Level Authorization
- Помимо этого, команда дебаг была дана без авторизации, то есть неавторизованный пользователь может видеть всю информацию обо всех пользователях, даже роль(администратор или нет). Далее были даны следующие команды:
  http://localhost:8080/users/v1/admin
  http://localhost:8080/users/v1/name1
Можно просматривать информацию об отдельных пользователях !без авторизации! Нельзя, чтобы любой неавторизованный пользователь мог просмотреть всю информацию о любом другом пользователе системы. Злоумышленник может просто вбить имя пользователя в url и получить конфиденциальные данные пользователя.

Меры предотвращения:
- добавить проверку авторизации на все эндпоинты, которые должны возвращать данные пользователей
- сделать так, чтобы обычные пользователя могли видеть только свой профиль, а администраторы - все
