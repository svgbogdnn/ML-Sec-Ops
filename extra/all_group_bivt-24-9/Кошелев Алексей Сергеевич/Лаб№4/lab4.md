### Фрагмент кода 2:
```python
from flask_wtf import Form  
from wtforms import TextField

class LoginForm(Form):  
    username = TextField('username')  
    password = TextField('password')
```
Недостаток заключается в том, что для пароля используется стандартный текстовый тип `TextField`. Из-за этого пароль при вводе будет отображаться на экране открытым текстом. В качестве мер противодействия необходимо использовать специализированное поле для паролей — `PasswordField`. Оно скроет вводимые символы и запретит браузеру кэшировать эти данные.

### Фрагмент кода 3:
```python
try:
    username = username.lower()
    email = email.strip().lower()
    user = User({'username': username, 'password': password, 'email': email, 'date_joined': curtime()})
    user.validate()
    save_user(self.db_conn, user)
except Exception, e:
    return self.render_template("success_create.html")
```
Недостаток заключается в том, что в блоке `except` перехватываются абсолютно все возможные исключения, но при любой ошибке пользователю всё равно возвращается страница успешной регистрации `success_create.html`. Также наблюдается отсутствие хэширования: Пароль пользователя (`password`) передается в модель и сохраняется в базу данных в открытом виде. Если база данных будет украдена, злоумышленники получат пароли всех пользователей. В качестве мер противодействия необходимо перехватывать только конкретные ошибки, возвращать пользователю шаблон с сообщением об ошибке, а не об успехе и обязательно хешировать пароль.

## Часть II. Изучение модели безопасности Django

### 1. Какие наиболее распространенные атаки предотвращает Django?
Фреймворк Django предоставляет встроенную защиту от следующих распространенных веб-уязвимостей:
* **XSS:** Шаблонизатор Django автоматически экранирует опасные символы при рендеринге HTML.
* **CSRF:** Встроенный middleware требует обязательного включения уникального токена `{% csrf_token %}` во все POST-формы.
* **SQL-инъекции:** Использование Django ORM для запросов к БД автоматически параметризует данные, разделяя логику запроса и пользовательский ввод.
* **Clickjacking:** Встроенный механизм `XFrameOptionsMiddleware` запрещает отображение сайта внутри iframe на других ресурсах.

### 2. Описать, как устроено управление пользовательскими сессиями в Django
Управление сессиями в Django реализовано через встроенный компонент `SessionMiddleware` и работает следующим образом:
1. **Хранение на стороне сервера:** В отличие от передачи всех данных в куках, Django хранит саму информацию сессии на сервере — в базе данных, файлах или кэше.
2. **Идентификатор сессии (Session ID):** Клиенту отправляется только случайно сгенерированный уникальный идентификатор сессии в виде cookie-файла (`sessionid`).
3. **Защита от кражи:** Django позволяет легко защитить куки с помощью флагов `HttpOnly` и `Secure`.
4. **Защита от фиксации сессии:** При успешном входе пользователя в систему Django автоматически генерирует новый ключ сессии, делая старый недействительным.
