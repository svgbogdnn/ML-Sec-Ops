##Часть I
###CVE за 2021 год, содержащие XSS в PHP-компонентах
За 2021 год в NVD зафиксировано более 1300 CVE, связанных с XSS-уязвимостями в компонентах, написанных на PHP. Это подтверждает, что даже хорошо изученная уязвимость продолжает массово встречаться в реальных продуктах.

**CVE-2021-24146**
Уязвимость в плагине Modern Events Calendar Lite для WordPress. Плагин предназначен для создания и отображения событий на сайте: конференции, вебинары, мероприятия, регистрация участников. Параметры запроса при экспорте событий не санитизировались перед выводом — неаутентифицированный атакующий мог внедрить произвольный JS через URL-параметры (Reflected XSS). Уязвимость затрагивала версии до 5.16.5.

**CVE-2021-24235**
Уязвимость в теме Goto Tour & Travel для WordPress. Тема предоставляет движок для сайтов турагентств: каталог туров, бронирование, отзывы, интеграция с платёжными шлюзами. Параметр поисковой формы не экранировался перед вставкой в HTML — атакующий мог сформировать ссылку с XSS-пейлоадом в параметре поиска и передать её жертве (Reflected XSS).

##Часть II
Скачал образ командой docker pull ket9/otus-devsecops-xss, затем запустил docker run -d -p 8080:80 ket9/otus-devsecops-xss:latest. Открыл http://localhost:8080/ — появилась главная страница с ссылками XSS-1 и index.php.
Перешёл по XSS-1 на http://localhost:8080/XSS-1/. Там раздел Comments с полем для ввода комментария и кнопкой Save Data. Поле ввода точка внедрения пользовательского ввода. Если приложение сохраняет текст и выводит его другим пользователям без экранирования, это Stored XSS

Сначала ввёл текст hi guys u menya vse nice и нажал Save Data. Страница обновилась и показала комментарий hi guys u menya vse nice. Приложение сохраняет данные и выводит их на странице — если ввод не фильтруется, HTML-теги тоже попадут в разметку. Затем написал <b>test</b> и убедился, что это действительно уязвимость
Затем ввёл пейлоад <script>alert('XSS')</script> и нажал Save Data. Страница перезагрузилась и браузер показал всплывающее уведомление с текстом XSS. Приложение не фильтрует ввод перед сохранением и не экранирует его при выводе — внедрённый тег script сохранился в базе и выполнился в контексте браузера.
Тип уязвимости: Stored XSS (Persistent XSS) — хранимый межсайтовый скриптинг. В отличие от Reflected XSS скрипт сохраняется на сервере и выполняется у каждого пользователя, открывшего страницу с комментариями, без необходимости заставлять жертву переходить по специальной ссылке

Меры предотвращения:
Экранировать специальные HTML-символы перед вставкой данных в разметку — заменять < на &lt;, > на &gt;, " на &quot;, ' на &#x27;, & на &amp;. В PHP для этого использовать htmlspecialchars($comment, ENT_QUOTES, 'UTF-8'). Также проверять ввод на соответствие ожидаемому формату и ограничивать длину. Дополнительно настроить заголовок Content-Security-Policy: default-src 'self'; script-src 'self' — тогда браузер заблокирует выполнение инлайн-скриптов даже если пейлоад попал в HTML. Флаг HttpOnly на сессионных куках не позволит украсть их через document.cookie при успешной XSS-атаке.
