# Лабораторная работа

**Базовая настройка безопасности Docker-контейнера**

---

## 🎯 Цель работы

Закрепить практические навыки обеспечения базовой безопасности Docker-контейнеров.

---

# Часть I. Анализ пользователя внутри контейнера

### Шаги выполнения:

1. Был загружен Docker-образ (alpine):

```bash
docker pull alpine
```

2. Получен список образов:

```bash
docker image ls
```

3. Определён пользователь на хостовой системе:

```bash
whoami
```

Результат:

```
zxc\sunik
```

4. Запущен контейнер:

```bash
docker run -it alpine sh
```

5. Проверен пользователь внутри контейнера:

```bash
whoami
```

Результат:

```
root
```

### Вывод:

По умолчанию контейнер запускается от пользователя **root**, что является небезопасной практикой, так как в случае компрометации злоумышленник получит максимальные привилегии внутри контейнера.

---

# Часть II. Запуск контейнера от non-root пользователя

### Dockerfile:

```dockerfile
FROM ket9/otus-devsecops-owasp-rest:latest

# создание пользователя и группы
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

# переключение на пользователя
USER appuser

EXPOSE 8080

# Дополнительные меры безопасности:
# - отказ от использования root пользователя
# - рекомендуется использовать фиксированную версию образа вместо latest
# - минимизация количества пакетов
# - использование read-only файловой системы (--read-only)
# - ограничение ресурсов (--memory, --cpus)
# - отключение capability (--cap-drop=ALL)
# - использование профилей безопасности (seccomp, apparmor)
```

---

### Сборка образа:

```bash
docker build -t secure-otus-app .
```

---

### Запуск контейнера:

```bash
docker run -it --entrypoint sh secure-otus-app
```

---

### Проверка пользователя:

```bash
whoami
```

Результат:

```
appuser
```

---

### Вывод:

Контейнер успешно запускается от непривилегированного пользователя (**non-root**), что значительно повышает уровень безопасности и снижает риски при возможной эксплуатации уязвимостей.

---

# ✅ Часть III. Сканирование безопасности образа

Сканирование выполнено с использованием инструмента Trivy.

### Команда:

```bash
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image secure-otus-app
```

---

### Результаты сканирования:

* Базовая ОС: Alpine Linux 3.14.2
* Всего уязвимостей: **72**

  * MEDIUM: 16
  * HIGH: 48
  * CRITICAL: 8

Уязвимости обнаружены:

* в системных пакетах (например, busybox)
* в Python-зависимостях (Flask, Jinja2, Werkzeug, urllib3 и др.)

---

### Анализ:

Основные причины наличия уязвимостей:

* использование устаревшего базового образа
* большое количество зависимостей
* устаревшие версии библиотек

Наличие большого количества HIGH и CRITICAL уязвимостей указывает на потенциальные риски:

* выполнение произвольного кода
* атаки типа Denial of Service
* эксплуатация известных CVE
* компрометация контейнера

---

### Рекомендации:

* использовать актуальные версии базовых образов
* отказаться от тега `latest`
* регулярно обновлять зависимости
* минимизировать количество устанавливаемых пакетов
* использовать multi-stage сборку
* регулярно проводить сканирование безопасности

---

### Сравнение:

Для сравнения был рассмотрен минималистичный образ Alpine Linux, в котором уязвимости отсутствовали.

Это демонстрирует, что увеличение количества зависимостей напрямую влияет на рост числа уязвимостей и увеличивает поверхность атаки.

В ходе лабораторной работы были изучены и применены базовые практики обеспечения безопасности Docker-контейнеров:

* выявлено, что по умолчанию контейнеры запускаются от root

* регулярности обновлений
