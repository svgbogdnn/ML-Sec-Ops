Часть 1

CVE-2021-26303

Суть ошибки : в финансовом трекере можно было использовать поле полного имени для stored XSS. PHP-компонент и его функционал : user-profile.php, видимо, обработка пользовательских профилей

CVE-2021-35438

Суть ошибки : в калькуляторе ip-адресов можно было использовать поле ip для reflected XSS. PHP-компонент и его функционал : ipcalc-result.php, result.php, судя по багрепорту, расчёт IPv4v6

Общее число уязвимостей

Тут несколько сложный вопрос, а что конкретно считать. Если в nvd забить в поиск php XSS (что, по идее, и надо было считать), мы получим 12 уязвимостей. Маловато. XSS : 764 уязвимости, 3% от общего числа. А вот это число как будто бы больше подходит под ожидания. Другие запросы, например, php execution дают, во-первых результаты, скорее похожие на первый, во-вторых, очевидным образом включают много того, что не XSS. Таким образом, я остановлюсь на числе 764, одновременно признавая его некоторую неточность.

Ход рассуждений

Окей, есть две ссылки: XSS-1 и index.php. По первой есть поле для комментов и кнопка save data. При нажатии на вторую не происходит ничего. Каждый раз, когда я нажимаю на save data, под надписью comments появляется новая строчка с введённым текстом. При этом этот список записей сохраняется. Попробую зайти с инкогнито, чтобы симулировать другого пользователя — список всё тут же. Огонь. Смотрю, как вообще работают инъекции в подобных условиях. Пробую вставить текст с html форматированием (test) — отображается test. Класс, сайт отображает введённый текст как html. Открываю сайт, нажимаю на XSS-1, получаю баннер: ![[Pasted image 20260428203802.png]] Успех

Тип уязвимости

Stored XSS : вредоносный скрипт сохраняется на сервере и "выдаётся" каждому новому пользователю, открывающему страницу.

Меры предотвращения

Для начала я бы запретил специальные символы html, например, > < " ' или &. Если это невозможно (эти символы могут встречаться в легитимном тексте) стал бы из экранировать: < заменял бы на &lt и т.д.

Также имеет смысл встроить сканер на конструкции типа \.

Добавил бы заголовок Content-Security-Policy: default-src 'self'; script-src 'self'; чтобы браузер мог выполнять только скрипты с сервера.
