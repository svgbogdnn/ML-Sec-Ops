Лабораторная работа:
Настройка безопасности Docker-контейнера

Часть I: Анализ прав пользователя

Цель: Узнать, от какого пользователя всё запускается в обычном образе из интернета.

Выбранный образ: tensorflow/tensorflow:nightly-jupyter

# Проверка пользователя внутри стандартного контейнера
docker run -it tensorflow/tensorflow:nightly-jupyter sh
whoami
# Результат: root
Вывод: В обычном образе мы сразу заходим как root (админ). Это опасно: если хакер взломает наше приложение, он сразу получит полные права внутри контейнера и сможет творить что угодно.
Рис 1. Проверка прав root в стандартном образе

Часть II: Защита через Dockerfile

Цель: Сделать свой образ, который запускается от обычного пользователя, а не от админа.

# Основная инструкция в Dockerfile для смены пользователя:
USER appuser

Проверка после сборки:

docker run -it tensorflow-secure whoami
# Результат: appuser
Вывод: Теперь мы работаем под обычным пользователем. Даже если хакер проберется внутрь, у него не будет прав админа, и он не сможет так просто захватить весь контейнер или сломать систему.
Рис 2. Подтверждение работы от имени appuser

Часть III: Анализ безопасности (Trivy)

Цель: Проверить наш образ на "дыры" (уязвимости) с помощью сканера Trivy.

Для получения сводной статистики использовалась команда:

docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image tensorflow-secure | Select-String -Pattern "Total:", "Target"

Результаты сканирования:

  • Итоговая статистика ОС: 1974 уязвимости (12 HIGH, 1812 MEDIUM, 150 LOW).
  • Критические ошибки: 0.
  • Python пакеты: 1 средняя ошибка в библиотеке pip.
Вывод: В образе много мелких дыр, так как базовый образ (Ubuntu) содержит много системных файлов. Самых страшных ошибок нет, но 12 опасных (HIGH) требуют внимания. Рекомендуется чаще обновлять зависимости и использовать "легкие" образы.
Рис 3. Итоговая статистика сканирования уязвимостей
