**Тип работы:** SAST-анализ мобильного приложения  
**Инструмент:** MobSF  
**Объект анализа:** APK мобильного приложения TikTok  
**Источник результатов:** `MobSf_report_tiktok.pdf` и сводный экран MobSF  

> Примечание: работа выполнена как альтернативный вариант задания, так как основной CI/CD pipeline не удалось корректно запустить. Вместо анализа пайплайна был проведён разбор отчёта статического анализа мобильного приложения.

## 1. Цель анализа

Целью работы является выявление потенциально опасных настроек и уязвимостей в Android-приложении по результатам статического анализа. В отчёте рассмотрены разрешения приложения, сетевые настройки, параметры манифеста и отдельные замечания по коду.

Основной акцент сделан на проблемах, которые могут повлиять на конфиденциальность данных пользователя, защищённость сетевого обмена и устойчивость криптографических механизмов.

## 3. Dangerous permissions

В приложении присутствуют разрешения Android, которые относятся к потенциально опасным, так как дают доступ к данным пользователя или к функциям устройства.

| Разрешение | Что позволяет | Почему это риск |
|---|---|---|
| `ACCESS_COARSE_LOCATION` | Получение приблизительного местоположения | Даже неточная геолокация позволяет строить профиль перемещений пользователя |
| `ACCESS_FINE_LOCATION` | Получение точной GPS-геолокации | Даёт возможность определять местоположение пользователя почти в реальном времени |
| `ACCESS_MEDIA_LOCATION` | Чтение геометок из медиафайлов | Через EXIF-данные фотографий и видео можно восстановить места съёмки |
| `BLUETOOTH_ADVERTISE` | Рекламирование устройства по Bluetooth | Может использоваться для обнаружения устройства рядом другими Bluetooth-устройствами |
| `BLUETOOTH_CONNECT` | Подключение к сопряжённым Bluetooth-устройствам | Расширяет поверхность атаки через взаимодействие с внешними устройствами |

**Вывод:** сами по себе разрешения не являются уязвимостью, но каждое из них должно быть обосновано функциональностью приложения. Чем больше опасных разрешений, тем выше риск злоупотребления ими или утечки пользовательских данных.

## 4. Network Security

В разделе сетевой безопасности MobSF выделил несколько проблем, часть из которых имеет уровень `HIGH`.

| № | Обнаруженная проблема | Уровень |
|---|---|---|
| 1 | Base config разрешает незашифрованный HTTP-трафик для всех доменов | HIGH |
| 2 | Base config содержит обход certificate pinning | HIGH |
| 3 | Domain config разрешает cleartext-трафик для `zero-rating.tiktok.com` | HIGH |
| 4 | Base config доверяет системным центрам сертификации | WARNING |

### Почему это опасно

Разрешение cleartext-трафика означает, что часть сетевого обмена может выполняться без TLS. В такой ситуации данные потенциально доступны для перехвата или изменения в сети, особенно если пользователь находится в публичной Wi-Fi-сети.

Отдельно стоит отметить проблему с certificate pinning. Если приложение допускает обход pinning или не фиксирует ожидаемый публичный ключ сервера, злоумышленнику проще провести MITM-атаку при наличии установленного пользовательского или скомпрометированного сертификата.

### Рекомендации

- запретить cleartext-трафик глобально;
- оставить HTTP только для технически обоснованных исключений, если они действительно необходимы;
- настроить строгую Network Security Config;
- применять Public Key Pinning для критичных API-доменов;
- пересмотреть доверие к системным CA, если приложение обрабатывает чувствительные данные.

## 5. Manifest Analysis

В AndroidManifest.xml обнаружены настройки, которые снижают общий уровень безопасности приложения.

| № | Проблема | Уровень | Объяснение |
|---|---|---|---|
| 1 | `minSdk=23` | HIGH | Приложение поддерживает Android 6.0. Эта версия устарела и давно не получает полноценные обновления безопасности |
| 2 | `android:usesCleartextTraffic=true` | HIGH | На уровне манифеста разрешён незашифрованный HTTP-трафик |

**Вывод:** сочетание устаревшей минимальной версии Android и разрешённого cleartext-трафика повышает риск эксплуатации известных уязвимостей платформы и перехвата данных.

## 6. Code Analysis

В отчёте также отмечены проблемы на уровне исходного/декомпилированного кода.

| № в отчёте | Проблема | CWE | Расположение | Уровень |
|---|---|---|---|---|
| 7 | Использование ECB-режима шифрования | CWE-327 | `X/C1531540pxZ.java` | HIGH |
| 9 | Использование слабого алгоритма шифрования | CWE-327 | `com/heytap/mcssdk/utils/c.java` | HIGH |
| 2 | Возможная запись чувствительных данных в логи | CWE-532 | `X/C1036660d5N.java` | INFO |

### Объяснение проблем

**ECB-режим шифрования** считается небезопасным, потому что одинаковые блоки открытого текста превращаются в одинаковые блоки шифротекста. Это позволяет атакующему анализировать структуру данных даже без знания ключа.

**Слабая криптография** относится к CWE-327 и означает применение устаревших или недостаточно стойких алгоритмов/режимов. Такие решения могут быть уязвимы к перебору, криптоанализу или практическим атакам на реализацию.

**Логирование чувствительных данных** опасно тем, что логи часто доступны разработчикам, системам мониторинга, crash-reporting сервисам или могут попасть в отчёты об ошибках. Если туда попадают токены, идентификаторы, персональные данные или ключевые параметры запросов, это становится каналом утечки.

## 7. План устранения замечаний

| Приоритет | Что исправить | Рекомендация |
|---|---|---|
| P1 | Cleartext HTTP | Установить `android:usesCleartextTraffic=false` и убрать разрешение HTTP из базовой Network Security Config |
| P1 | Certificate pinning bypass | Удалить обход pinning и внедрить проверку публичных ключей для основных API-доменов |
| P2 | ECB и слабая криптография | Заменить небезопасные режимы на `AES/GCM/NoPadding` или `ChaCha20-Poly1305`; использовать уникальный IV/nonce |
| P2 | Устаревшая минимальная версия Android | Поднять `minSdkVersion` минимум до Android 10, если это допустимо по требованиям продукта |
| P3 | Dangerous permissions | Оставить только действительно необходимые разрешения и запрашивать их в момент использования функции |
| P3 | Запись данных в логи | Исключить из логов токены, персональные данные, параметры авторизации и другие чувствительные значения |

---

## 8. Итоговый вывод

Статический анализ показал несколько значимых проблем безопасности. Наиболее критичными являются разрешённый незашифрованный сетевой трафик, проблемы с certificate pinning и использование небезопасных криптографических подходов. Эти замечания напрямую связаны с риском перехвата данных, MITM-атак и раскрытия чувствительной информации.

Отдельного внимания требуют опасные разрешения Android. Они могут быть оправданы функциональностью приложения, однако должны использоваться по принципу минимально необходимого доступа: запрашиваться только при необходимости, сопровождаться понятным объяснением для пользователя и регулярно пересматриваться.

В качестве первоочередных действий рекомендуется усилить сетевую конфигурацию, отказаться от слабой криптографии, ограничить список разрешений и исключить возможность попадания чувствительных данных в логи.
