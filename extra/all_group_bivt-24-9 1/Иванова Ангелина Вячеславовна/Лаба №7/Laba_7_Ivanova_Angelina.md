# ЛР 7. Инструмент SAST-анализа и проведение SAST-тестирования

**Приложение:** Telegram 12.7.3

**Общий рейтинг безопасности:** 44/100

## 1. Опасные разрешения приложения

**Разрешения геолокации (ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, ACCESS_BACKGROUND_LOCATION)**

**Описание проблемы:**
Приложение запрашивает доступ к точной и приблизительной геолокации, а также к геолокации в фоновом режиме. Это создает риски несанкционированного отслеживания местоположения пользователя и повышенного расхода заряда батареи

**План митигации:**
Реализовать запрос разрешений геолокации только в момент использования соответствующих функций (runtime permissions)
Добавить понятное обоснование для пользователя, зачем приложению нужен доступ к геолокации
Реализовать возможность работы приложения без предоставления доступа к геолокации
Добавить индикатор активности геолокации в интерфейсе приложения

Приоритет: Высокий

**Разрешения доступа к контактам (READ_CONTACTS, WRITE_CONTACTS, GET_ACCOUNTS)**

**Описание проблемы:**
Приложение имеет полный доступ к чтению и записи контактов пользователя, а также к списку аккаунтов на устройстве. При компрометации приложения злоумышленник может получить доступ ко всей адресной книге пользователя

**План митигации:**
Реализовать синхронизацию контактов только по явному запросу пользователя
Добавить настройку для полного отключения синхронизации контактов
Реализовать локальное шифрование базы контактов
Добавить информацию о использовании контактов в политику приватности

Приоритет: Высокий

**Разрешения записи аудио и доступа к камере (RECORD_AUDIO, CAMERA)**

**Описание проблемы:**
Приложение может записывать аудио и делать фотографии/видео без ведома пользователя. Это создает риски несанкционированной записи приватных разговоров

**План митигации:**
Реализовать индикатор активности микрофона и камеры в системной панели уведомлений
Запрашивать разрешения только при активации функций голосовых сообщений или видеозвонков
Автоматически очищать кэш записей после их отправки или отмены

Приоритет: Высокий

**Разрешение чтения журнала вызовов (READ_CALL_LOG)**

**Описание проблемы:**
Приложение может читать журнал телефонных звонков пользователя, что является чувствительной информацией

**План митигации:**
Пересмотреть необходимость данного разрешения для функционала мессенджера
Если разрешение не критично - удалить из манифеста
Если необходимо - запросить только при использовании конкретной функции и объяснить пользователю причину

Приоритет: Средний

**Разрешение доступа к хранилищу (READ_EXTERNAL_STORAGE, WRITE_EXTERNAL_STORAGE, READ_MEDIA_IMAGES, READ_MEDIA_VIDEO, READ_MEDIA_AUDIO)**

**Описание проблемы:**
Приложение имеет широкий доступ к файлам на устройстве, включая изображения, видео и аудио файлы

**План митигации:**
Использовать Scoped Storage для Android 10+ вместо общих разрешений
Запрашивать доступ к конкретным файлам через системный файловый picker
Ограничить доступ только к необходимым типам файлов

Приоритет: Высокий

# УЯЗВИМОСТИ MANIFEST ANALYSIS

**Включен cleartext traffic (android:usesCleartextTraffic=true)**

**Описание проблемы:**
Приложение разрешает использование незашифрованного HTTP-трафика, что делает возможным перехват данных злоумышленником через MITM-атаку.

**План митигации:**
Установить android:usesCleartextTraffic="false" в AndroidManifest.xml
Настроить network_security_config.xml с разрешением HTTPS только для доверенных доменов
Реализовать Certificate Pinning для критически важных API endpoints
Обновить все API endpoints на использование HTTPS

Приоритет: КРИТИЧЕСКИЙ

**Поддержка устаревших версий Android (minSdk=23)**

**Описание проблемы:**
Приложение может устанавливаться на Android 6.0, который больше не получает обновлений безопасности от Google

**План митигации:**
Поднять minSdkVersion до 29 (Android 10) для получения современных механизмов безопасности
Уведомить пользователей о необходимости обновления ОС
Прекратить поддержку устаревших версий Android

Приоритет: Высокий

**Экспортированные компоненты без защиты (exported components)**

**Описание проблемы:**
Многие Activities, Services, Broadcast Receivers и Content Providers экспортированы и доступны другим приложениям на устройстве без защиты

**План митигации:**
Добавить android:exported="false" для всех компонентов, не предназначенных для внешнего использования
Для публичных компонентов добавить android:permission с кастомными разрешениями
Реализовать валидацию всех входящих Intent данных
Провести аудит всех exported компонентов

Приоритет: Высокий

**Отсутствует verification App Links (assetlinks.json)**

**Описание проблемы:**
Для доменов telegram.me, telegram.dog, t.me отсутствует файл assetlinks.json для верификации App Links. Это позволяет злоумышленникам перехватывать URL и проводить фишинговые атаки

**План митигации:**
Разместить файл .well-known/assetlinks.json на всех доменах приложения
Добавить android:autoVerify="true" в intent-filter Activities
Протестировать верификацию ссылок

Приоритет: Высокий

# УЯЗВИМОСТИ СЕТЕВОЙ БЕЗОПАСНОСТИ

**Отсутствие защиты сетевого трафика**

**Описание проблемы:**
Отсутствует полноценная конфигурация network security для защиты сетевого трафика

**План митигации:**
Настроить network_security_config.xml с принудительным HTTPS
Включить HSTS (HTTP Strict Transport Security)
Реализовать Certificate Transparency
Настроить регулярную ротацию SSL сертификатов

Приоритет: Высокий

# УЯЗВИМОСТИ АНАЛИЗА КОДА

**Небезопасный генератор случайных чисел**

**Описание проблемы:**
В коде обнаружено использование java.util.Random вместо криптографически стойкого генератора. Это может привести к предсказуемости генерируемых значений (токенов, ключей)

**План митигации:**
Заменить java.util.Random на java.security.SecureRandom во всех местах генерации криптографических значений
Провести аудит всех мест генерации токенов, сессионных идентификаторов и ключей
Добавить статический анализ в CI/CD pipeline для предотвращения подобных проблем

Приоритет: Средний

**Логирование чувствительной информации**

**Описание проблемы:**
В коде присутствует логирование информации, которое может содержать чувствительные данные

**План митигации:**
Отключить логирование в production сборках
Использовать ProGuard/R8 для удаления отладочного кода
Реализовать безопасное логирование без PII (Personally Identifiable Information)
Провести ревью всех логов на предмет чувствительных данных

Приоритет: Средний
