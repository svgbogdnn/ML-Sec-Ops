# ЛР 6

1. **Hardcoded Admin Backdoor (Жёстко заданный бэкдор администратора)**

**Расположение:** Файл webgoat-5.4/src/main/java/org/owasp/webgoat/lessons/BlindScript.java, метод executeBackDoor, строка с условием if ("B_Admin443".equals(me))

**Почему это секрет:** В коде жёстко прописана строка-пароль B_Admin443. При её передаче в параметре person метод s.setAdmin(true) предоставляет пользователю права администратора в обход стандартной аутентификации

**Правильный способ хранения:** Логика предоставления прав администратора должна контролироваться только через безопасную систему аутентификации и авторизации. Пароли и бэкдоры не должны существовать в коде. Нужно полностью удалить метод executeBackDoor и вызовы к нему, настроить RBAC на уровне сервера и провести аудит кода на наличие подобных скрытых триггеров

2. **Obfuscated Data Exfiltration URL (Обфусцированный URL для эксфильтрации данных)**

**Расположение:** Файл BlindScript.java, статическое поле private final static String WEBGOAT_URL = "aHR0cDovL2xvY2FsaG9zdC9XZWJHb2F0L2NhdGNoZXI/UFJPUEVSVFk9eWVz"; (строка ~70).

**Почему это секрет:** Строка закодирована в Base64 (при декодировании получается http://localhost/WebGoat/catcher?PROPERTY=yes). Используется в методе executeSpyWare для отправки списка файлов из кэша браузера пользователя на внешний (или локальный) сервер. Обфускация скрывает адрес назначения от быстрого анализа

**Правильный способ хранения:** Легитимные эндпоинты должны храниться в конфигурационных файлах или переменных окружения, которые не попадают в Git. Необходимо удалить метод executeSpyWare и переменную WEBGOAT_URL

3. **Client-Side Encrypted Coupon Codes (Зашифрованные купоны на клиенте)**

**Расположение:** Файл webgoat-5.4/src/main/webapp/javascript/clientSideValidation.js, строка 2: var coupons = ["nvojubmq", "emph", "sfwmjt", ...];

**Почему это секрет:** Валидные промокоды хранятся в клиентском JavaScript-файле. Они зашифрованы слабым алгоритмом (шифр Цезаря), а функция дешифровки decrypt() также доступна клиенту. Любой пользователь может декодировать массив и получить рабочие купоны, что ведёт к финансовым потерям

**Правильный способ хранения:** Валидация купонов должна происходить исключительно на стороне сервера. Клиент должен отправлять введённый код на бэкенд, где система проверяет его в БД и возвращает результат (true/false). Нужно удалить массив coupons и функцию decrypt из клиентского кодаи реализовать API-эндпоинт на сервере для проверки кодов

4. **Hardcoded Easter Egg / Logic Backdoor (Скрытый Easter Egg)**

**Расположение:** Файл BlindScript.java, метод createContent, строка if ("BrucE".equals(person.toString()))

**Почему это секрет:** При вводе имени "BrucE" приложение автоматически помечает урок как пройденный без выполнения реальных условий задания

**Правильный способ хранения:** Состояние прохождения уроков должно зависеть только от корректного выполнения упражнений и сохраняться в сессии или БД на основе объективных данных. Нужно удалить условные блоки с Easter Eggs из продакшен-кода. Если они нужны для обучения, вынести их в отдельный конфигурируемый режим, который отключается в production

5. **Hardcoded Destructive File Path (Жёстко заданный путь для удаления файлов)**

**Расположение:** Файл BlindScript.java, внутренний класс Deleter, метод compose, строка: File foo = new File("C:\\temp\\user.txt");

**Почему это секрет:** В коде динамически компилируется класс, который удаляет файл по жёстко заданному пути. Это может быть путь к важным системным файлам или данным пользователей. Жёсткая привязка к пути C:\temp\... указывает на опасную логику

**Правильный способ хранения:** Пути к файлам должны конфигурироваться через внешние настройки. Операции удаления должны проходить валидацию и логироваться.Нужно удалить классы Deleter и ResidentJavaFileObject и запретить динамическую компиляцию кода из строк в рантайме
