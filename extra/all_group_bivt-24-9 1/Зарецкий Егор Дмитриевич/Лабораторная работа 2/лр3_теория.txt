ЛАБОРАТОРНАЯ РАБОТА 3. 3 CVE, СВЯЗАННЫЕ С OWASP API Security Top 10

1) CVE-2025-27505 (GeoServer REST API)
    Источник: NVD (опубликована в 2025)

    Суть уязвимости:
        Возможен обход защиты REST API и неавторизованный доступ к индексной странице API
        Фильтр защищает /rest и /rest/**, но не варианты вида /rest.html

    Причина:
        Некорректная проверка/сопоставление путей в security-конфигурации (Missing Authorization, CWE-862)

    К какому пункту OWASP API Top 10 относится:
        API5: Broken Function Level Authorization (и в целом проблема авторизации на уровне маршрутов)

    Риск:
        Утечка служебной информации об установленных расширениях и доступных API-поверхностях

    Меры предотвращения:
        Обновить GeoServer до исправленных версий
        Закрыть все варианты путей (/rest.*, /rest/**) в фильтрах
        Ограничить доступ к административным API по сети (впн ip allowlost) 


2) CVE-2024-0404 (AnythingLLM, endpoint /api/invite/:code)
    Источник: NVD (опубликована в 2024)

    Суть уязвимости:
        Mass Assignment в REST endpoint регистрации по инвайту
        Злоумышленник может добавить поле role=admin в тело запроса и создать привилегированную учетную запись

    Причина:
        Отсутствие allowlist/blocklist для полей, принимаемых из JSON
        Небезопасное связывание входных полей с моделью пользователя

    К какому пункту OWASP API Top 10 относится:
        I3: Broken Object Property Level Authorization (бывшая категория Mass Assignment)

    Риск:
        Эскалация привилегий до администратора, полный контроль над системой

    Меры предотвращения:
        Использовать DTO с жестким белым списком разрешенных полей
        Игнорировать чувствительные поля (role, is_admin, permissions и т.п.) на публичных endpoint
        Ввести серверные проверки ролей и отдельные endpoint для админ функций


3) CVE-2024-36467 (Zabbix API, method user.update)
    Источник: NVD (опубликована в 2024)

    Суть уязвимости:
        Аутентифицированный пользователь с доступом к user.update может добавить себя в административные группы
        Это приводит к повышению привилегий через API

    Причина:
        Недостаточная проверка авторизации на уровне бизнес-функции (Improper Authorization, CWE-285)

    К какому пункту OWASP API Top 10 относится:
        API5: Broken Function Level Authorization

    Риск:
        Получение административных прав обычным пользователем

    Меры предотвращения:
        Патч до версий с исправлением от вендора
        Явно запретить изменение usrgrps для непривилегированных юзеров
        Реализовать принцип минимально необходимых прав для API методов

ВЫВОД:
    Во всех трех случаях корневая проблема недостаточный контроль авторизации в REST API на уровне маршрута, функции или свойств объекта. 
    Это напрямую укладывается в категории OWASP API Top 10 и показывает, что даже незначительные ошибки в валидации путей или полей запроса приводят к критичной эскалации привилегий
