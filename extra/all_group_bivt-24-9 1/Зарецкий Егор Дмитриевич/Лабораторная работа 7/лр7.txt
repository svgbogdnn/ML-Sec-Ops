РЕЗУЛЬТАТЫ

MobSF поставил приложению 52 балла из 100

1. Опасные разрешения (dangerous)

REQUEST_INSTALL_PACKAGES - может ставить APK изнутри приложения
CAMERA - доступ к камере (скорее всего для QR-кодов)
POST_NOTIFICATIONS - пуши 

Из 25 «подозрительных разрешений сработало только 3. Для впн клиента
это нормально но REQUEST_INSTALL_PACKAGES это проблема тк 
через него можно подсунуть подменный APK

2. Сетевая безопасность (high+)

В жсон раздел network_findings пустой, но проблемы нашлись в других местах

Manifest, high:
usesCleartextTraffic=true - приложение разрешает обычный HTTP без
шифрования В публичной сети можно перехватить конфиги серверов и токены

Code, high:
Insecure SSL в Conscrypt.java приложение доверяет любым сертификатам
в том числе self-signed. Это уязвимость к MITM, для
впн клиента плохо

При этом MobSF нашёл и SSL pinning в трёх файлах то есть защита есть
но она противоречит trust-all видимо в разных частях кода разная
логика работы с сертификатами.

3. Манифест (high+)
High:
minSdk=21 - можно поставить на старый Android 5.0 без патчей
usesCleartextTraffic=true - HTTP разрешён глобально

Warning:
allowBackup=true - через adb можно снять бэкап с данными приложения
WidgetProvider открыт для других приложений
BootUpReceiver, QSTileService, FirebaseInstanceIdReceiver - тоже
exported надо проверять кто к ним имеет доступ

Зато exported activities = 0 внутренние экраны снаружи не вызываются
Это хорошо 

4. Анализ кода (high+)

High:
android_insecure_ssl - trust all certificates в Conscrypt.java:257

Warning (основное):
hardcoded credentials в AuthData.java, MetaParams.java, XRayConfig.java
IP-адреса прямо в коде (16 файлов)
raw SQL-запросы - риск SQL injection (11 файлов)
небезопасный Random, SHA-1, запись во внешнее хранилище и temp-файлы
запрос рут прав

Из плюсов: SSL pinning и root detection

Secrets 46 штук, среди них google_crash_reporting_api_key и строки
типа inbound_authorization_password.

5. Сертификат

Подпись v1 + v2 + v3. Есть предупреждение про Janus vulnerability
на старых Android 5.0-8.0 из-за v1 схемы

Что из этого следует

Главная проблема это сеть С одной стороны pinning с другой trust all
certificates и разрешённый хттп. Для приложения, которое хранит конфиги
прокси-серверов, это серьёзно.

В коде нашлись захардкоженные ключи и пароли при декompиляции через JADX
их легко достать

Raw скл в 11 файлах если туда попадёт пользовательский ввод, можно
получить injection в локальную базу с настройками серверов

allowBackup + запись на внешнее хранилище - конфиги впн можно вытащить
через adb backup или с SD карты

REQUEST_INSTALL_PACKAGES - лишний вектор если источник обновлений
не контролируется жёстко.

ВЫВОДЫ

Просканировал Happ но андроид версию то же самое, что стоит у меня
на маке по идее. Оценка 52/100: приложение в целом нормальноре (современный
targetSdk 36, закрытые activity, есть pinning и root detection), но
сетевые настройки и работа с секретами сделаны с вопросами 

MobSF хорошо подходит для такого тестирования быстро даёт структурированный
отчёт с разбивкой по permissions, manifest, code и secrets. можно встроить его в сисд в рельыне проекиы
