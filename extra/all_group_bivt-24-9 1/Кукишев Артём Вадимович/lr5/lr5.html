1. Исходное состояние

  • Базовый образ: ubuntu:latest
  • Права доступа: По умолчанию внутри контейнера использовался суперпользователь root, что является нарушением принципа наименьших привилегий.
  • Результат сканирования (Trivy): Выявлено значительное количество уязвимостей уровня ОС (в таких пакетах, как tar, libc6, mount, login и др.). Для большинства из них отсутствовали патчи (статус affected). Изначальное количество уязвимостей: 20.

2. Внесенные изменения

Для устранения выявленных проблем безопасности был применен подход минимизации поверхности атаки (Attack Surface Reduction):

  1. Смена базового образа: Осуществлен переход с "толстого" образа ubuntu на легковесный и безопасный alpine:latest.
  2. Отказ от root-прав: В Dockerfile добавлены инструкции для создания системной группы и непривилегированного пользователя (appuser).
  3. Hardening в Runtime: Контейнер запускался с дополнительными флагами защиты:
    • --read-only (запрет записи в файловую систему)
    • --cap-drop=ALL (сброс расширенных прав ядра)
    • --security-opt no-new-privileges:true (защита от эскалации привилегий)

3. Итоговый результат

  • Финальный образ: secure-alpine
  • Права доступа: Процессы внутри контейнера успешно работают от имени непривилегированного пользователя appuser.
  • Результат сканирования (Trivy): Количество уязвимостей снижено до 0 .

Вывод

Лабораторная работа наглядно демонстрирует, что использование стандартных публичных образов без настройки несет высокие риски информационной безопасности. Замена базового образа на минималистичный (Alpine/Distroless) в сочетании с отказом от использования пользователя root является наиболее эффективным и быстрым методом базовой защиты Docker-контейнеров.

DockerFile

FROM alpine:latest

RUN apk update && apk upgrade --no-cache

RUN addgroup -S devsecops && adduser -S appuser -G devsecops

USER appuser

EXPOSE 8080

CMD ["sh"]

# В самом Dockerfile:
# 1. HEALTHCHECK --interval=30s CMD wget -q -O - http://localhost:8080/ || exit 1 
# 2. Использование Alpine радикально уменьшает поверхность атаки (Attack Surface)
# 3. Отказ от пользователя root (USER appuser).
#
# Флаги безопасности при запуске контейнера (docker run):
# 1. --read-only : Запрещает запись в файловую систему контейнера.
# 2. --security-opt no-new-privileges:true : Защита от повышения привилегий
# 3. --cap-drop=ALL : Сброс расширенных прав ядра Linux.
