# Лабораторная работа №3 (XSS в PHP)

## Часть 1

### CVE-2021-43698
**Источник:** https://nvd.nist.gov/vuln/detail/CVE-2021-43698

**Компонент:** phpWhois — написан на PHP, предназначен для получения информации о доменах через протоыкол WHOIS.

**Недостаток:** В файле example.php функция exit выводит сообщение, которое содержит значение $_GET['query'] без обработки. Через параметр query можно передать скрипт, который выполнится в браузере. Это XSS.

### CVE-2021-45416
**Источник:** https://nvd.nist.gov/vuln/detail/CVE-2021-45416

**Компонент:** RosarioSIS — написан на PHP (файл modules/Scheduling/Courses.php), используется для управления учебным процессом (расписание, курсы).

**Недостаток:** Через параметр search_term в скрипте Courses.php можно внедрить произвольный HTML/JavaScript. Ввод не фильтруется, код отражается на странице. Это reflected XSS.

## Часть 2

Запустим контейнер:
docker pull ket9/otus-devsecops-xss
docker run -d -p 8080:80 --name xss-lab ket9/otus-devsecops-xss:latest

Перейдём http://localhost:8080
На странице написано XSS lab, есть ссылка XSS-1 и index.php.

### XSS-1 (Stored)

Перейдём по XSS-1. Там форма с полем comment? и кнопкой Save Data.

Введём скрипт:
<script>alert('xss-test')</script>
Сохраним и обновим страницу. Вылезло окно с текстом xss-test — значит, скрипт остался на сервере и выполняется при каждом открытии.

Вывод: ввод никак не фильтруется, попадает в HTML как есть. Это хранимый XSS.

## Найденная уязвимость
Хранимый XSS (Stored XSS). Код сохраняется на сервере и срабатывает у всех, кто заходит на страницу.

## Меры предотвращения
- Экранировать вывод.
- Проверять входные данные, разрешать только текст без тегов.
- Поставить Content Security Policy (CSP), чтобы ограничить выполнение скриптов.
- Не вставлять пользовательский ввод напрямую в HTML.
