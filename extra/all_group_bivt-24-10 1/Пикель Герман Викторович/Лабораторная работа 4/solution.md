Фрагмент кода 2:

```python
from flask_wtf import Form  
from wtforms import TextField

class LoginForm(Form):  
username = TextField('username')  
password = TextField('password')
```

Недостатков тут несколько. Во-первых, форма LoginForm не содержит валидации входных данных (то есть можно передать потенциально некорректный ввод). Во-вторых, пароль будет храниться в виде обычного текста. В третьих, flask_wtf - устаревший вариант использования форм и надо использовать современный FlaskForm.

Рекомендации по улушению кода: добавить валидацию полей и использовать специальное поле для ввода пароля PasswordField.

### Часть 2.

_Какие наиболее распространенные атаки предотвращает django?_

1. SQL-инъекции. От них защищает встроенный ORM.
2. XSS-атаки. Шаблонизатор джанго автоматически экранирует все введенное.
3. CSRF-атаки. Если в форме не прописать {% csrf_token %}, то запрос даже не получится отправить.
4. Атаки через подделку заголовка Host в запросе.
5. Можно самостоятельно и быстро настроить зашиту от небезопасных кук и сессий

_Описать, как устроено управление пользовательскими сессиями в django_

Пользователь заходит на сайт, и сразу же джанго создает для него сессию. После этого в браузер пользователя отправляется этот куки с идентификатором сессии.
При следующих пользовательских запросах браузер отправляет этот куки обратно. Джанго по предоставленному идентификатору находит данные сессии в хранилище (в кэше, бд, а может и вовсе в файлах на серваке) и понимает, кто пользователь и какие данные его.
