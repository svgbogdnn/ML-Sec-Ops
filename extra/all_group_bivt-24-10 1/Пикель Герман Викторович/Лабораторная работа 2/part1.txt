1. CVE-2025-12903
Ссылка на ресурс: https://nvd.nist.gov/vuln/detail/CVE-2025-12903

В общем, в плагине Payment Plugins Braintree For WooCommerce у REST-эндпойнта wc-braintree/v1/3ds/vaulted_nonce отсутствовала корректная проверка прав.
В результате чего злоумышленник, который не был аутентифицирован в систему мог получить payment method nonces для чужих сохраненныъ платежных токенов. Это позволяло проводить мошеннические транзакции и привязывать платежные методы других пользователей к совершенно другим и чужим подпискам. Относится этот случай очевидно к категории OWASP Broken Object Level Authorization.
Недостаток был в том что REST API принимал пользовательский token ID и возвращал результат без предварительной проверки на то, что запрос посылал действительно владелец этого токена.
Причина произошедшего заключалась в следующем: 
- эндпоинт  был зарегистрирован с permission_callback = __return_true
- сервер обрабатывал переданные пользователем token IDs без проверки ownership и без аутентификации.


2. CVE-2025-56449
Ссылка на ресурс: https://nvd.nist.gov/vuln/detail/CVE-2025-56449

Описание проблемы такое: В Obsidian Scheduler REST API версии 5.0.0–6.3.0 учётная запись, которая была заблокирована в веб-интерфейсе из-за неисполнения MFA-требования, все еще могла выполнять административные действия через REST API по базовой аутентификации. В частности, так можно было использовать default admin и создать нового привилегированного пользователя, обходя многофакторную аутентификацию. Этот случай относится к категории OWASP Broken Authentication.
Недостаток состоял в том, что система считала пользователя заблокированным в UI, но вот REST API продолжал работать с Basic Auth и авторизовывал административные запросы. То есть через UI доступ был запрещен, а через API доступ не был запрещен.
Причина была в том, что логика аутентификации или доступа между UI и REST API не была синхронизирована.

3. CVE-2026-34839
Ссылка на ресурс: https://nvd.nist.gov/vuln/detail/CVE-2026-34839

В Glances до версии 4.5.4 REST API /api/4/* был доступен без аутентификации и одновременно разрешал запросы с любого ресурса из-за Access-Control-Allow-Origin: * в миддлвейре. Это позволяло вредоносному сайту читать чувствительные данные из работающего экземпляра Glances в браузере жертвы. Относится этот случай к категории OWASP API8:2023 Security Misconfiguration.
Недостаток был в том что REST API был одновременно открыт без аутентификации и был доступе к чтению браузера с произвольного сайта из-за разрешений в CORS.
Причины такой уязвимости в отсутствии аутентификации для /api/4/* и плохо реализованная CORS-политика.
