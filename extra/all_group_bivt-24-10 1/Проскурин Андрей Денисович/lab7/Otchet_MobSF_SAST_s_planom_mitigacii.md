
## Развернуть инструмент SAST-анализа и провести SAST-тестирование

**Дисциплина:** Внедрение и работа в DevSecOps  
**Инструмент:** Mobile Security Framework — MobSF  
**Тип анализа:** Static Analysis / SAST  
**Объект анализа:** Android APK-файл  
**Формат приложения:** `.apk`

---

В рамках работы были выполнены
- развернут MobSF
- загружен APK-файл мобильного приложения
- выполнен статический анализ приложения
- изучены результаты по permissions, network security, manifest analysis и code analysis
- составлен план митигации обнаруженных рисков

---

## 2. Развертывание MobSF

Для выполнения задания я использовал локальное развертывание MobSF через Docker.

Команда для загрузки образа:

```bash
docker pull opensecurity/mobile-security-framework-mobsf:latest
```

Команда для запуска контейнера:

```bash
docker run -it --rm -p 8000:8000 opensecurity/mobile-security-framework-mobsf:latest
```

После запуска MobSF был доступен в браузере по адресу:

```text
http://127.0.0.1:8000
```

Вход был выполнен с использованием стандартных учетных данных MobSF:

```text
login: mobsf
password: mobsf
```

После входа я перешёл к загрузке APK-файла для анализа.

## 3. Загрузка APK и запуск анализа

В интерфейсе MobSF был выбран APK-файл мобильного приложения. После загрузки MobSF автоматически запустил статический анализ.

В процессе анализа MobSF проверил:

- AndroidManifest.xml;
- используемые permissions;
- network security configuration;
- параметры сборки приложения;
- потенциально опасные участки кода;
- использование небезопасных API;
- наличие признаков небезопасной работы с данными.

После завершения анализа был сформирован отчет MobSF.

## 4. Результаты SAST-анализа

### 4.1 App Permissions

В разделе **App Permissions** были обнаружены разрешения со статусом `dangerous`.

Основные опасные разрешения:

| Permission                                  | Уровень риска | Описание риска                                                      |
| ------------------------------------------- | ------------: | ------------------------------------------------------------------- |
| `android.permission.CAMERA`                 |     Dangerous | Приложение может получать доступ к камере устройства.               |
| `android.permission.RECORD_AUDIO`           |     Dangerous | Приложение может записывать звук с микрофона.                       |
| `android.permission.READ_EXTERNAL_STORAGE`  |     Dangerous | Приложение может читать пользовательские файлы.                     |
| `android.permission.WRITE_EXTERNAL_STORAGE` |     Dangerous | Приложение может изменять или сохранять файлы во внешнем хранилище. |
| `android.permission.ACCESS_FINE_LOCATION`   |     Dangerous | Приложение может получать точное местоположение пользователя.       |

**Вывод:** приложение запрашивает чувствительные разрешения, которые могут приводить к утечке персональных данных при некорректной реализации контроля доступа или избыточном сборе данных.

---

### 4.2 Network Security

В разделе **Network Security** были выделены проблемы высокого уровня риска.

Основные замечания:

| Проблема | Severity | Риск |
|---|---:|---|
| Cleartext traffic разрешён | High | Передача данных по HTTP может привести к перехвату трафика. |
| Недостаточно строгая TLS-конфигурация | High | Возможен downgrade или использование слабых параметров соединения. |
| Отсутствие certificate pinning | Medium / High | При компрометации доверенного CA возможна MITM-атака. |

**Вывод:** сетевые настройки приложения требуют ужесточения. Главный риск связан с возможностью передачи или перехвата чувствительных данных при недостаточно защищенном соединении.


---

### 4.3 Manifest Analysis

В разделе **Manifest Analysis** были обнаружены потенциально опасные настройки приложения.

Основные проблемы:

| Проблема | Severity | Описание |
|---|---:|---|
| `android:debuggable="true"` | High | Debug-режим не должен быть включён в production-сборке. |
| `android:allowBackup="true"` | High | Возможна выгрузка данных приложения через backup-механизмы. |
| Exported components | High | Экспортированные Activity/Service/Receiver могут быть вызваны другими приложениями. |
| Использование опасных intent-filter | Medium / High | Возможны некорректные внешние вызовы компонентов приложения. |

**Вывод:** настройки манифеста содержат риски, связанные с отладкой, резервным копированием и доступностью внутренних компонентов приложения извне.

---

### 4.4 Code Analysis

В разделе **Code Analysis** были обнаружены проблемы высокого уровня риска.

Основные замечания:

| Проблема | Severity | Риск |
|---|---:|---|
| Hardcoded sensitive information | High | В коде могут присутствовать ключи, токены или служебные значения. |
| Insecure random number generator | High | Небезопасная генерация случайных значений может повлиять на токены или идентификаторы. |
| Logging sensitive data | High | Чувствительные данные могут попадать в логи. |
| Небезопасная работа с WebView | High | Возможны XSS, загрузка небезопасного контента или выполнение JavaScript. |
| Использование устаревших API | Medium / High | Повышает вероятность эксплуатации известных уязвимостей. |

**Вывод:** часть рисков связана с небезопасной обработкой чувствительных данных и использованием потенциально опасных механизмов Android API.

---

## 5. Общий анализ обнаруженных недостатков

По итогам SAST-анализа можно выделить несколько групп проблем:

1. **Избыточные разрешения приложения.**  
   Приложение запрашивает доступ к камере, микрофону, файлам и геолокации. Такие разрешения должны использоваться только при реальной необходимости.

2. **Недостаточно защищенная сетевая конфигурация.**  
   Разрешение cleartext traffic и отсутствие certificate pinning повышают риск MITM-атак.

3. **Проблемные настройки AndroidManifest.xml.**  
   Включенный debug-режим, разрешенный backup и exported-компоненты увеличивают поверхность атаки.

4. **Проблемы в коде приложения.**  
   В коде обнаружены потенциально опасные практики: хранение чувствительных данных, логирование, небезопасная работа с WebView и использование слабых механизмов генерации случайных значений.

## 6. План митигации рисков

| № | Обнаруженный риск | Приоритет | План митигации | Ожидаемый результат |
|---:|---|---:|---|---|
| 1 | Избыточные dangerous permissions | High | Провести ревизию всех permissions. Удалить разрешения, которые не нужны для бизнес-функций приложения. Для оставшихся разрешений добавить runtime-запрос и пояснение пользователю. | Снижение риска несанкционированного доступа к данным пользователя. |
| 2 | Доступ к камере и микрофону | High | Ограничить использование только конкретными сценариями. Добавить контроль доступа на уровне UI и бизнес-логики. | Исключение скрытого или неконтролируемого сбора аудио/видео. |
| 3 | Доступ к внешнему хранилищу | High | Перейти на scoped storage. Не хранить чувствительные данные во внешнем хранилище. | Снижение риска утечки файлов и персональных данных. |
| 4 | Cleartext traffic разрешён | High | Запретить HTTP-трафик через `networkSecurityConfig` и использовать только HTTPS. | Исключение передачи данных по незащищенному каналу. |
| 5 | Отсутствие certificate pinning | Medium / High | Реализовать certificate pinning для критичных API-запросов. | Снижение риска MITM-атак. |
| 6 | Debug-режим в production | High | Установить `android:debuggable="false"` для release-сборок. Проверить Gradle-конфигурацию. | Исключение отладочных возможностей в production. |
| 7 | Разрешенный backup | High | Установить `android:allowBackup="false"` или настроить backup rules с исключением чувствительных данных. | Снижение риска извлечения данных приложения через backup. |
| 8 | Exported components | High | Для всех компонентов явно указать `android:exported`. Закрыть компоненты, которые не должны быть доступны извне. Добавить permission-защиту для необходимых exported-компонентов. | Уменьшение поверхности атаки. |
| 9 | Hardcoded secrets | High | Удалить ключи и токены из кода. Перенести секреты в защищенное хранилище или backend. Провести ротацию скомпрометированных значений. | Исключение утечки секретов из APK. |
| 10 | Логирование чувствительных данных | High | Удалить логи с персональными данными, токенами, session id и параметрами авторизации. Отключить debug-логи в release. | Снижение риска раскрытия данных через логи. |
| 11 | Небезопасная работа с WebView | High | Отключить JavaScript, если он не нужен. Запретить загрузку file:// URL. Ограничить домены через allowlist. | Снижение риска XSS и небезопасной загрузки контента. |
| 12 | Использование устаревших API | Medium | Обновить зависимости и SDK. Проверить совместимость после обновления. | Снижение риска эксплуатации известных уязвимостей. |

## 7. Приоритизация исправлений

Исправления стоит выполнять в следующем порядке:

1. Отключить debug-режим и запретить backup в production-сборке.
2. Запретить cleartext traffic и оставить только HTTPS.
3. Проверить exported-компоненты и закрыть лишние.
4. Удалить hardcoded secrets и выполнить ротацию ключей.
5. Убрать логирование чувствительных данных.
6. Провести ревизию dangerous permissions.
7. Настроить certificate pinning для критичных API.
8. Повторно просканировать APK в MobSF после исправлений.
