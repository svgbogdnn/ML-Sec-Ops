## CVE-2025-63783 — Broken Object Level Authorization (BOLA)  
  
### Описание  
  
Уязвимость обнаружена в REST API приложения Onlook (tRPC mutation endpoints).  
Атакующий может изменить параметр `project_id` в запросе и получить доступ к объектам других пользователей (просмотр, изменение, удаление).  
  
### Суть уязвимости  
  
REST API не выполняет проверку принадлежности объекта пользователю.  
Доступ к ресурсу определяется только по идентификатору объекта без проверки прав доступа.  
  
### Причины возникновения  
  
- Отсутствие проверки авторизации на уровне объекта  
- Доверие пользовательскому вводу (`project_id`)  
- Отсутствие централизованного механизма контроля доступа  
  
### OWASP API Top 10  
  
- API1: Broken Object Level Authorization (BOLA)  
  
### Последствия  
  
- Доступ к чужим данным  
- Возможность изменения или удаления ресурсов других пользователей  
- Нарушение конфиденциальности данных

## CVE-2025-27505 — Broken Authentication / Security Misconfiguration  
  
### Описание  
  
В GeoServer REST API обнаружена ошибка конфигурации безопасности.  
Атакующий может получить доступ к REST API без аутентификации, используя обход маршрутов (например `/rest.html`).  
  
### Суть уязвимости  
  
REST API защищён неполностью, что позволяет обходить механизмы аутентификации через альтернативные URL.  
  
### Причины возникновения  
  
- Неполная защита REST маршрутов  
- Ошибки в security filters  
- Некорректная обработка URL-паттернов  
  
### OWASP API Top 10  
  
- API2: Broken Authentication  
- API7: Security Misconfiguration  
  
### Последствия  
  
- Доступ к API без авторизации  
- Возможность разведки системы  
- Потенциальная утечка данных

## CVE-2025-55210 — Broken Authentication + Broken Function Level Authorization  
  
### Описание  
  
В FreePBX API модуле обнаружена уязвимость, позволяющая подделывать JWT токены и получать доступ к REST/GraphQL API с повышенными привилегиями.  
  
### Суть уязвимости  
  
Система некорректно проверяет JWT токены, что позволяет использовать поддельные или модифицированные токены для доступа к защищённым функциям API.  
  
### Причины возникновения  
  
- Некорректная валидация JWT подписи  
- Отсутствие проверки roles/scopes  
- Слабая реализация механизма авторизации  
  
### OWASP API Top 10  
  
- API2: Broken Authentication  
- API5: Broken Function Level Authorization  
  
### Последствия  
  
- Эскалация привилегий  
- Доступ к административным функциям API  
- Полный контроль над частью системы  
  
---  
  
## Итог  
  
Рассмотренные уязвимости относятся к следующим категориям OWASP API Top 10:  
  
- Broken Object Level Authorization (BOLA)  
- Broken Authentication  
- Security Misconfiguration  
- Broken Function Level Authorization  
  
---  
  
## Вывод  
  
Основные причины уязвимостей REST API:  
  
- отсутствие проверки прав доступа на уровне объектов  
- ошибки конфигурации маршрутов API  
- некорректная реализация JWT и механизмов авторизации

## Анализ REST API  
  
В ходе исследования были обнаружены следующие эндпоинты:
- GET /users/v1 — получение списка пользователей  
- GET /users/v1/{username} — получение информации о пользователе  
- GET /users/v1/_debug — получение расширенной информации  
- POST /users/v1/login — аутентификация пользователя  
  
---  
  
## Уязвимость №1 — Broken Object Level Authorization (BOLA)  
  
### Описание  
  
Обнаружена возможность получения данных пользователей без прохождения аутентификации.  
  
### Эксплуатация  
  
GET /users/v1/admin  
GET /users/v1/name1  
  
Ответ сервера:  
  
{  
"username": "admin",  
"email": "admin@mail.com"  
}  
  
---  
  
### Суть проблемы  
  
Отсутствует проверка прав доступа к объектам. Доступ к данным определяется исключительно значением параметра username, без проверки прав пользователя.  
  
### Классификация OWASP  
  
API1: Broken Object Level Authorization (BOLA)  
  
---  
  
## Уязвимость №2 — Excessive Data Exposure  
  
### Описание  
  
Выявлен debug endpoint, возвращающий избыточные и чувствительные данные пользователей.  
  
### Эксплуатация  
  
GET /users/v1/_debug  
  
Ответ сервера:  
  
{  
"users": [  
{  
"username": "name1",  
"email": "mail1@mail.com",  
"password": "pass1",  
"admin": false  
},  
{  
"username": "name2",  
"email": "mail2@mail.com",  
"password": "pass2",  
"admin": false  
},  
{  
"username": "admin",  
"email": "admin@mail.com",  
"password": "pass1",  
"admin": true  
}  
]  
}  
  
---  
  
### Суть проблемы  
  
API возвращает данные, не предназначенные для внешнего доступа, включая пароли и информацию о правах пользователей.  
  
### Классификация OWASP  
  
API3: Excessive Data Exposure  
  
---  
  
## Уязвимость №3 — Broken Authentication (цепочка атаки)  
  
### Описание  
  
Использование данных, полученных через debug endpoint, позволяет выполнить аутентификацию и изменить данные администратора.  
  
### Эксплуатация  
  
1. Получение учетных данных:  
  
GET /users/v1/_debug  
Пароль администратора: pass1  
  
2. Аутентификация:  
  
POST /users/v1/login  
{  
"username": "admin",  
"password": "pass1"  
}  
  
Получен auth_token.  
  
3. Изменение данных:  
  
PUT /users/v1/admin/email  
Authorization: Bearer TOKEN  
  
{  
"email": "hacked@mail.com"  
}  
  
4. Результат:  
  
{  
"username": "admin",  
"email": "hacked@mail.com"  
}  
  
---  
  
### Суть проблемы  
  
Отсутствует защита от использования скомпрометированных учетных данных и недостаточная проверка авторизации при изменении данных.  
  
### Классификация OWASP  
  
API2: Broken Authentication  
  
---  
  
## Общие выводы  
  
В ходе работы выявлены следующие уязвимости:  
  
- Broken Object Level Authorization (BOLA)  
- Excessive Data Exposure  
- Broken Authentication  
  
---  
  
## Меры защиты  
  
- реализация строгой проверки авторизации на уровне объектов  
- исключение возврата чувствительных данных  
- отключение debug-эндпоинтов в production  
- хранение паролей в виде хешей  
- использование RBAC/ABAC  
- проверка прав доступа при всех изменяющих операциях  
  
---  
  
## Заключение  
  
В процессе анализа REST API были выявлены критические уязвимости, позволяющие осуществлять несанкционированный доступ к данным пользователей и их модификацию при наличии скомпрометированных учетных данных.
