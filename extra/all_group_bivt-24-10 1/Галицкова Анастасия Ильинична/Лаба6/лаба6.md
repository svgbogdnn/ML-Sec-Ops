## Секрет №1 — Пароль в .env файле

**Файл:** `docker/.env`, строки 3–4

```
USER=alex675
PASSWORD=#!qerge34t423sdfvdsfgeR
```

Это реальные логин и пароль, скорее всего от приватного репозитория пакетов. Файл `.env` не должен попадать в репозиторий - его нужно добавить в `.gitignore`, а сами значения хранить в секретах CI/CD платформы

## Секрет №2 — Приватный RSA-ключ

**Файл:** `webgoat-server/privatekey.key`

```
-----BEGIN PRIVATE KEY-----
MIIEvgIBADANBgkqhkiG9w0BAQEFAASC...
-----END PRIVATE KEY-----
```

Приватный ключ в репозитории - критическая утечка. С его помощью можно расшифровывать трафик и подделывать подписи. Хранить такие вещи нужно в Vault или KMS

## Секрет №3 — GitHub токен в workflows

**Файл:** `.github/workflows/release.yml`, строка 75

```yaml
# правильно было так:
GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

# а стало вот так:
GITHUB_TOKEN: cee3257f0e59d1d4975a35429cffc3d8b5fabe15ca2e9d47243cbc446d4894a5
```

Токен захардкожен прямо в файле — любой кто видит репозиторий, видит и токен. Нужно всегда использовать `${{ secrets.GITHUB_TOKEN }}`, токены в коде не хранить.

## Секрет №4 — App Secret

**Файл:** `docker/.env`, строка 2

```
APP_SECRET=666666666666666
```

Это ключ для подписи сессий и CSRF-токенов приложения. Значение слабое и предсказуемое, плюс оно открыто лежит в репозитории. Должно быть случайным и храниться только в переменных окружения.

## Секрет №5 — CSR файл

**Файл:** `webgoat-server/certificatesigningrequest.csr`

```
-----BEGIN CERTIFICATE REQUEST-----
MIIC4zCCAcsCAQAwdDEL...
-----END CERTIFICATE REQUEST-----
```

Это запрос на подпись сертификата — пара к приватному ключу из секрета №2. Содержит данные об организации. В репозитории не должен быть, передавать его нужно напрямую в Certificate Authority.
