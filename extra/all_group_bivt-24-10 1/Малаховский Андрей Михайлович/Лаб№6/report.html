1. Используемый инструмент

Для проверки репозитория был выбран инструмент truffleHog.

truffleHog — это инструмент для поиска секретов в git-репозиториях. Он анализирует историю изменений, коммиты, ветки и diff-файлы. Инструмент может находить:

  • пароли;
  • токены доступа;
  • приватные ключи;
  • секреты приложений;
  • строки с высокой энтропией;
  • другие чувствительные данные.

Особенность инструмента заключается в том, что он проверяет не только актуальное состояние файлов, но и историю git. Это важно, потому что даже если секрет был удален из текущей версии файла, он мог остаться в старых коммитах.

4. Запуск сканирования

Сканирование репозитория было выполнено командой:

trufflehog https://github.com/OtusTeam/DevSecOps_secret-finding.git | tee -a log.txt

Команда tee -a log.txt использовалась для того, чтобы одновременно вывести результат проверки в терминал и сохранить его в файл log.txt.

После выполнения проверки лог был просмотрен командой:

cat log.txt | more

Так как вывод оказался очень большим, дополнительно были использованы команды фильтрации по ключевым словам:

grep -n -i -B6 -A8 "GITHUB_TOKEN:" log.txt > useful.txt
grep -n -i -B6 -A8 "PASSWORD=" log.txt >> useful.txt
grep -n -i -B6 -A8 "APP_SECRET" log.txt >> useful.txt
grep -n -i -B6 -A15 "BEGIN PRIVATE KEY" log.txt >> useful.txt
grep -n -i -B6 -A15 "BEGIN RSA PRIVATE KEY" log.txt >> useful.txt

Затем был просмотрен сокращенный файл с полезными находками:

cat useful.txt | more

2 webgoat-server/privatekey.key, строка 1 -----BEGIN PRIVATE KEY----- Это приватный криптографический ключ. Приватные ключи не должны храниться в репозитории, так как они могут использоваться для аутентификации, подписи, TLS или других криптографических операций. При утечке такого ключа злоумышленник может использовать его как доверенный ключ. Хранить приватные ключи в защищенном хранилище секретов: HashiCorp Vault, Kubernetes Secrets, Docker Secrets или CI/CD Secrets. Удалить файл privatekey.key из репозитория. Считать найденный ключ скомпрометированным. Перевыпустить новый приватный ключ и сертификат, если он использовался. Добавить *.key, *.pem, *.p12, *.jks в .gitignore. Удалить старый ключ из истории git с помощью BFG Repo-Cleaner или git filter-repo.
