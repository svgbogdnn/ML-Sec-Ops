## Часть 2

На скриншоте показано создание файла Dockerfile с помощью текстового редактора `nano`.
![[Pasted image 20260429172710.png]]

В Dockerfile был указан образ FROM httpd:alpine. Потом добавил команды для создания отдельного пользователя `appuser` и группы `appgroup`. Также была изменена настройка Apache: порт 80 заменен на 8080, чтобы приложение могло запускаться от непривилегированного пользователя.

Главная настройка безопасности в данном Dockerfile - USER appuser. То есть после сборки контейнер будет запускаться не от пользователя `root`, а от обычного пользователя `appuser`.

Также я указал открываемый порт - EXPOSE 8080 и команда запуска Apache: CMD 
["httpd-foreground"] 
Дополнительные настройки безопасности указаны в виде комментариев, как и требовалось по заданию.
![[Pasted image 20260429222532.png]]

Дальше собрал образ.  Docker выполнил инструкции из Dockerfile: взял базовый образ `httpd:alpine`, создал пользователя `appuser`, изменил порт Apache на 8080, назначил права на директории и указал запуск от пользователя appuser.  
В конце видно, что образ успешно собрался и получил тег `httpd-secure:lab`.
![[Pasted image 20260429172730.png]]

На скриншоте выполнена команда `docker image ls`.  
В списке локальных образов появился новый образ `httpd-secure` с тегом `lab`. То есть сборка собственного образа прошла успешно.
![[Pasted image 20260429172736.png]]

Дальше выполнил запуск контейнера командой `docker run --rm -it --entrypoint sh httpd-secure:lab`.  
После входа внутрь контейнера команда `whoami` вывела `appuser`. Это подтверждает, что контейнер запускается не от root-пользователя.  
Команда `id` дополнительно показала идентификатор пользователя `uid=100(appuser)` и группу `gid=101(appgroup)`.
![[Pasted image 20260429172740.png]]

## Часть 3
Для проверки безопасности собранного образа был использован сканер Trivy.  
  
Была выполнена команда:  
  
```bash  
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v "$HOME/.cache/trivy:/root/.cache/" aquasec/trivy:latest image httpd-secure:lab
```

При первом запуске Docker скачал образ `aquasec/trivy:latest`, так как он отсутствовал. После этого Trivy скачал актуальную базу уязвимостей и выполнил сканирование образа `httpd-secure:lab`.

![[Pasted image 20260429223440.png]]
Это итоговый результат проверки. 
Trivy определил тип образа как `alpine` версии `3.23.4`. В столбце `Vulnerabilities` указано значение `0`, то есть известных уязвимостей в образе не обнаружено.  
В столбце `Secrets` стоит `-`, что означает, что секреты не сканировались или не были отображены в итоговой таблице.

**Вывод**: по результатам сканирования Trivy в образе `httpd-secure:lab` не обнаружены известные уязвимости. Значение `0` в столбце `Vulnerabilities` означает, что на момент проверки образ считается чистым по базе уязвимостей Trivy. Однако образ необходимо регулярно обновлять и повторно сканировать, так как база уязвимостей постоянно обновляется.
