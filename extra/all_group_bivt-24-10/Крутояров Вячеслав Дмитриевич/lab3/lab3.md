## Часть 1

# 1. CVE-2021-29624 (Уязвимость в phpMyAdmin)
https://nvd.nist.gov/vuln/detail/CVE-2021-29624

Назначение компонента: phpMyAdmin — это самое популярное веб-приложение с открытым исходным кодом, написанное на PHP. Оно предназначено для администрирования баз данных MySQL и MariaDB через браузер. Функционал включает создание таблиц, выполнение SQL-запросов, управление пользователями и экспорт/импорт данных

Описание уязвимости: Была обнаружена Reflected XSS. В панели поиска (при специфическом URL) пользовательский ввод не экранировался, что позволяло злоумышленнику сформировать вредоносную ссылку. При переходе по ней администратором, в его браузере выполнялся JS-код

# 2. CVE-2021-21311 (Уязвимость в Adminer)
https://nvd.nist.gov/vuln/detail/CVE-2021-21311

Назначение компонента: Adminer (ранее phpMinAdmin) — это легковесный инструмент управления базами данных, написанный в виде одного PHP-файла. Это более легкая альтернатива phpMyAdmin. Он поддерживает MySQL, PostgreSQL, SQLite и другие СУБД, предоставляя интерфейс для работы с таблицами и запросами

Описание уязвимости: В компоненте была найдена XSS в механизме вывода сообщений об ошибках базы данных. Если сервер базы данных возвращал ошибку, содержащую HTML-теги, Adminer выводил её без предварительной очистки

# 3. Подсчет общего количества CVE за 2021 год
За 2021 год в Национальной базе данных уязвимостей (NVD) было зарегистрировано 20 169 новых CVE (согласно статистике NIST). Из них несколько тысяч (более 2500) относятся к различным видам XSS (Cross-Site Scripting), что доказывает: несмотря на возраст уязвимости, она по-прежнему остается одной из самых массовых в веб-разработке

## Часть 2
Зашел на http://localhost:8080/, увидел там ссылки на XSS-1 и index.php

Перешел по ссылке http://localhost:8080/XSS-1/ и увидел поле коммента

В поле ввел: <script>alert('Попытка исполнить код')</script>

Нажал Save Data, после чего в браузере сразу высветилось всплывающее окно с текстом "Попытка исполнить код"

При перезагрузке страницы это окно появлялось снова. Из этого я сделал вывод, что введенный скрипт сохранился на стороне сервера (в БД или файле) и теперь автоматически встраивается в исходный код страницы при каждом ее запросе

Тип уязвимости - Stored XSS (Хранимая межсайтовая уязвимость)
Приложение принимает данные от пользователя без должной проверки и очистки. В результате браузер интерпретирует выводимый текст не как обычную строку, а как исполняемый JS код, и запускает его в контексте сессии клиента

# Меры предотвращения
Основная защита — строгое экранирование спецсимволов перед тем, как выводить пользовательские данные на страницу. Необходимо преобразовывать опасные символы в безопасные HTML-сущности:
Символ < заменять на &lt;
Символ > заменять на &gt;
Символ " заменять на &quot;
Символ ' заменять на &#x27;
Символ & заменять на &amp;
