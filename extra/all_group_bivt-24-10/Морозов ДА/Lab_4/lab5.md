## 1. Какие наиболее распространенные атаки предотвращает Django?

Django имеет встроенные механизмы защиты от распространенных веб-уязвимостей.

Основные атаки, от которых защищает Django:

- **XSS** — Django по умолчанию экранирует данные в шаблонах, поэтому вредоносный HTML или JavaScript не выполняется как код.
- **CSRF** — Django использует CSRF-токены, которые проверяются при отправке форм и POST-запросов.
- **SQL injection** — При использовании Django ORM данные передаются в запросы безопасно, без прямой подстановки пользовательского ввода в SQL.

## 2. Как устроено управление пользовательскими сессиями в Django?

Сессии нужны для хранения информации о пользователе между запросами. Так как HTTP не хранит состояние, Django использует session cookie.

Обычно процесс работает так:

1. Пользователь заходит на сайт.
2. Django создает для него случайный `session_id`.
3. Этот `session_id` отправляется пользователю в cookie.
4. Браузер пользователя сохраняет cookie и отправляет ее при следующих запросах.
5. Django по `session_id` находит данные сессии на сервере.
6. Через `request.session` приложение может читать и изменять данные сессии.

По умолчанию данные сессий могут храниться в базе данных, но Django также поддерживает хранение в кэше, файлах или подписанных cookies.

Для безопасности сессий используются следующие механизмы:

- cookie подписываются, чтобы пользователь не мог незаметно изменить данные.
- `HttpOnly` запрещает JavaScript получать доступ к session cookie.
- `Secure` позволяет передавать cookie только по HTTPS.
- `SameSite` ограничивает отправку cookie при межсайтовых запросах.
- сессии имеют срок жизни и могут автоматически удаляться.
