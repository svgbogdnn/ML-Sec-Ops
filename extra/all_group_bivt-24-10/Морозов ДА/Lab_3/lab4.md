# Симуляция XSS-атаки

## Часть 1

### CVE-2021-27330

Источник: https://nvd.nist.gov/vuln/detail/CVE-2021-27330

Уязвимость была найдена в Triconsole Datepicker Calendar. Это PHP-компонент календаря, который используется для выбора даты через форму на сайте. Обычно такие компоненты применяются в формах регистрации, бронирования, заказов и других страницах, где пользователь должен выбрать дату.

Проблема была в XSS в файле calendar_form.php. Через специальный параметр злоумышленник мог передать JavaScript-код, который потом выполнялся в браузере пользователя.

Причина: приложение выводило данные пользователя на страницу без фильтрации и экранирования специальных символов.

### CVE-2021-43683

Источник: https://nvd.nist.gov/vuln/detail/CVE-2021-43683

Уязвимость была обнаружена в pictshare v1.5. Это PHP-приложение для хранения и публикации изображений. Пользователь может загружать картинки и получать ссылки для просмотра.

Проблема находилась в api/info.php. Приложение брало параметр hash из URL и выводило его обратно пользователю. Из-за этого злоумышленник мог вставить JavaScript-код и добиться его выполнения в браузере.

Причина: параметр из запроса выводился без проверки и экранирования HTML-символов.

---

### CVE-2021-24177

Источник: https://nvd.nist.gov/vuln/detail/CVE-2021-24177

Уязвимость была найдена в WordPress plugin File Manager до версии 7.1. Этот плагин используется для управления файлами сайта через админ-панель WordPress.

Проблема заключалась в reflected XSS. JavaScript-код можно было передать через User-Agent, после чего он отображался в ответе приложения.

Причина: приложение не фильтровало и не экранировало пользовательский ввод.

## Часть 2

После открытия XSS-1 появилась простая форма с полем comment?. Сначала решил проверить, отображается ли пользовательский ввод на странице. В поле был введён текст: test

После отправки формы текст появился на странице. Из этого был сделан вывод, что приложение выводит пользовательский ввод обратно в HTML-страницу.

---

После этого решил попробовать самый простой XSS payload: `<script>alert(1)</script>`

После отправки формы в браузере появилось всплывающее окно с числом 1. Даже после обновления страницы, алёрт остался. Это подтвердило, что JavaScript-код выполняется в контексте браузера пользователя.

---

Найденная уязвимость относится к XSS

---

## Причина уязвимости

Причина проблемы заключается в том, что приложение вставляет пользовательские данные прямо в HTML-код страницы без экранирования специальных символов. Браузер воспринимает тег `<script>` как настоящий JavaScript-код и выполняет его.

---

## Меры предотвращения

Для защиты от XSS необходимо фильтровать и экранировать пользовательский ввод. В первую очередь нужно экранировать специальные HTML-символы: <, >, ", ' и тд.

Дополнительно полезно использовать: валидацию входных данных, ограничение HTML-тегов.
