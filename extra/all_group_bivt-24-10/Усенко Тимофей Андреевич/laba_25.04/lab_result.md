# Лабораторная работа: безопасность docker-контейнера

## Часть 1

Скачал образ alpine, посмотрел список образов на машине. До запуска контейнера выполнил whoami — вывело timofeyusenko. Запустил контейнер и выполнил whoami внутри — вывело root. То есть по умолчанию контейнер запускается от суперпользователя, что не очень хорошо с точки зрения безопасности.

## Часть 2

Написал dockerfile на основе alpine. Создал отдельного пользователя appuser и переключился на него через USER. Также добавил комментарии с рекомендуемыми флагами запуска.

```dockerfile
FROM alpine:latest

# запускаем приложение не от root для безопасности
# при запуске контейнера рекомендуется использовать флаги:
# read-only файловая система только для чтения
# no-new-privileges запрет получения новых привилегий
# cap-drop ALL сброс всех linux capabilities
# memory 128m ограничение памяти

RUN addgroup -S appgroup && adduser -S appuser -G appgroup

USER appuser

WORKDIR /home/appuser

CMD ["sh"]
```

Собрал образ командой docker build -t secure-alpine . и запустил с флагами --cap-drop ALL и --memory 128m. Внутри контейнера whoami вернул appuser — значит приложение больше не крутится от root.

## Часть 3

Прогнал образ через trivy. Он скачал базу уязвимостей и просканировал образ. Результат — 0 уязвимостей.

Это ожидаемо для alpine, потому что в нём минимум пакетов и соответственно минимум потенциальных дыр. Если бы взял ubuntu или debian — уязвимостей было бы намного больше. В реальных проектах такое сканирование стоит запускать регулярно, особенно после добавления новых пакетов.
