Отчёт о проведении SAST-анализа мобильного приложения

Лабораторная работа №7

1. Введение

1.1 Цель работы

Развернуть инструмент SAST-анализа мобильных приложений (MobSF) и провести тестирование безопасности мобильного приложения.

1.2 Инструментарий

  • Инструмент: Mobile Security Framework (MobSF) v3.x
  • Способ развёртывания: Docker Container
  • Объект анализа: TikTok.apk (com.zhiliaoapp.musically)
  • Версия приложения: 32.7.4
  • Размер: 67.3 МБ

1.3 Методология

SAST (Static Application Security Testing) — метод анализа безопасности приложений, который проверяет исходный код и бинарные файлы без выполнения программы. MobSF автоматически анализирует:

  • AndroidManifest.xml
  • Сетевую конфигурацию
  • Разрешения приложения
  • Исходный код на наличие уязвимостей
  • Hardcoded secrets

2. Развёртывание MobSF

2.1 Установка через Docker

# Создание директории для данных
mkdir -p ~/mobsf-data

# Запуск контейнера MobSF
docker run -it --rm \
  -p 8000:8000 \
  -v ~/mobsf-data:/home/mobsf/MobSF/userdata \
  opensecurity/mobile-security-framework-mobsf:v3.1.1

2.2 Проверка работоспособности

После запуска контейнера веб-интерфейс доступен по адресу:

4.2 App Permissions — Опасные разрешения

MobSF обнаружил 6 разрешений со статусом dangerous.

Разрешение Уровень риска Описание угрозы
ACCESS_FINE_LOCATION High Точное GPS-отслеживание в реальном времени. Риск утечки геоданных и слежки за пользователем
ACCESS_COARSE_LOCATION Medium Приблизительное местоположение через сеть. Может использоваться для профилирования
ACCESS_MEDIA_LOCATION Medium Извлечение геолокации из EXIF-данных фотографий и видео. Утечка метаданных
CAMERA Medium Доступ к камере. Риск несанкционированной съёмки
RECORD_AUDIO Medium Запись звука с микрофона. Перехват приватных разговоров
READ_CONTACTS High Полный доступ к контактам. Утечка личных данных третьих лиц

Анализ:

  • Для видеоприложения разрешения CAMERA и RECORD_AUDIO обоснованы
  • ACCESS_FINE_LOCATION избыточно — достаточно приблизительной геолокации для рекомендаций контента
  • READ_CONTACTS критично — не очевидно зачем приложению доступ к контактам

Рекомендации:

  1. Запрашивать разрешения в рантайме, а не при установке
  2. Объяснять пользователю цель каждого запроса
  3. Предоставлять fallback для пользователей, отказавших в разрешениях
  4. Удалить READ_CONTACTS если функционал не требует доступа к адресной книге

4.3 Network Security — Уязвимости сетевой безопасности

Обнаружено 4 проблемы уровня HIGH и выше.

HIGH-1: Cleartext HTTP разрешён глобально

Severity: HIGH
CWE: CWE-319 (Cleartext Transmission of Sensitive Information)

Описание: В AndroidManifest.xml установлен флаг:

<application
    android:usesCleartextTraffic="true"
    ... >

Это разрешает передачу данных по незашифрованному HTTP для всех доменов.

Риск:

  • Перехват трафика злоумышленником (MITM-атака)
  • Утечка чувствительных данных (токены, персональная информация)
  • Подмена контента и инъекция вредоносного кода

Митигация:

<application
    android:usesCleartextTraffic="false"
    android:networkSecurityConfig="@xml/network_security_config"
    ... >

Создать res/xml/network_security_config.xml:

<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <base-config cleartextTrafficPermitted="false">
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </base-config>
</network-security-config>

HIGH-2: Обход Certificate Pinning

Severity: HIGH
CWE: CWE-295 (Improper Certificate Validation)

Описание: В конфигурации сети обнаружен механизм обхода проверки сертификатов (certificate pinning bypass).

Риск:

  • Возможность подделки SSL-сертификата
  • Перехват зашифрованного трафика через прокси (Charles, mitmproxy)
  • Компрометация защищённых каналов связи

Митигация:

  • Удалить код, позволяющий обходить certificate pinning
  • Внедрить строгий Public Key Pinning для критичных API-доменов
  • Использовать библиотеки с автоматической проверкой сертификатов (OkHttp, Retrofit)

HIGH-3: Cleartext для zero-rating.tiktok.com

Severity: HIGH
Описание: В domain-specific конфигурации разрешён HTTP-трафик для домена zero-rating.tiktok.com.

Риск:

  • Специфичный домен для zero-rating (бесплатный трафик) передаёт данные без шифрования
  • Утечка метаданных о пользователях

Митигация:

  • Настроить HTTPS для всех доменов без исключений
  • Использовать HSTS (HTTP Strict Transport Security)

WARNING: Доверие системным сертификатам

Severity: WARNING
Описание: Приложение доверяет всем системным CA-сертификатам по умолчанию.

Рекомендация:

  • Ограничить список доверенных CA только необходимыми
  • Использовать custom CA для внутренних сервисов

4.4 Manifest Analysis — Анализ AndroidManifest.xml

Обнаружено 2 проблемы уровня HIGH и 37 предупреждений.

HIGH-1: Устаревший minSdkVersion

Severity: HIGH
Проблема: minSdkVersion=23 (Android 6.0 Marshmallow)

Риск:

  • Android 6.0 не получает обновления безопасности с 2019 года
  • Известные уязвимости платформы остаются неисправленными
  • Отсутствие современных механизмов защиты (Scoped Storage, Privacy Features, Runtime Permissions)

Митигация:

android {
    defaultConfig {
        minSdkVersion 29  // Android 10
        targetSdkVersion 33
    }
}

Обоснование:

  • Android 10+ получают регулярные security patches
  • Современные механизмы защиты приватности
  • Улучшенная работа с разрешениями

HIGH-2: Глобальный cleartext traffic

Severity: HIGH
Проблема: android:usesCleartextTraffic="true" в <application>

Риск: (см. Network Security HIGH-1)

Митигация: (см. выше)

WARNING: Экспортированные компоненты

Количество: 26 Activity, 3 Service, 5 BroadcastReceiver

Проблема: Компоненты объявлены с android:exported="true" без защиты android:permission.

Риск:

  • Любое приложение может вызвать Activity/Service
  • Утечка данных через Intent
  • Запуск компонентов злоумышленником

Митигация:

<activity
    android:name=".MainActivity"
    android:exported="false" />

<!-- Или с защитой -->
<activity
    android:name=".SensitiveActivity"
    android:exported="true"
    android:permission="com.tiktok.permission.ACCESS_ACTIVITY" />

4.5 Code Analysis — Уязвимости в коде

Обнаружено 3 проблемы уровня HIGH и 10 предупреждений.

HIGH-1: ECB-режим шифрования

Severity: HIGH
CWE: CWE-327 (Use of a Broken or Risky Cryptographic Algorithm)
Файл: X/C1531540pxZ.java

Описание: Используется режим ECB (Electronic Codebook) для шифрования данных. Одинаковые блоки открытого текста дают одинаковые блоки шифротекста.

Риск:

  • Паттерны в данных остаются видимыми
  • Возможность криптоанализа
  • Не соответствует современным стандартам безопасности (NIST)

Митигация:

// НЕБЕЗОПАСНО:
Cipher.getInstance("AES/ECB/PKCS5Padding")

// БЕЗОПАСНО:
Cipher.getInstance("AES/GCM/NoPadding")  // с уникальным IV
// ИЛИ
Cipher.getInstance("AES/CBC/PKCS5Padding")  // с случайным IV

HIGH-2: Слабый алгоритм шифрования

Severity: HIGH
CWE: CWE-327
Файл: com/heytap/mcssdk/utils/c.java

Описание: Используется устаревший или слабый криптографический алгоритм (возможно DES, 3DES или RC4).

Риск:

  • Алгоритм может быть взломан brute-force
  • Не соответствует современным стандартам (NIST, FIPS)
  • Уязвимость к криптоанализу

Митигация:

  • Заменить на AES-256-GCM или ChaCha20-Poly1305
  • Использовать ключи длиной минимум 256 бит
  • Реализовать правильное управление ключами (Android KeyStore)

HIGH-3: World Writable SharedPreference

Severity: HIGH
CWE: CWE-732 (Incorrect Permission Assignment for Critical Resource)
Файл: SettingsFragmentDelegate.java, yd/E.java

Описание: Файл или SharedPreference создан с флагом MODE_WORLD_WRABLE. Любое приложение может записать данные в этот файл.

Риск:

  • Любое приложение с разрешением на чтение внешнего хранилища может получить доступ к данным
  • Возможность инъекции вредоносных данных
  • Утечка токенов и настроек

Митигация:

// НЕБЕЗОПАСНО:
getSharedPreferences("prefs", Context.MODE_WORLD_WRABLE);

// БЕЗОПАСНО:
getSharedPreferences("prefs", Context.MODE_PRIVATE);

Если данные нужно расшарить с другим приложением — использовать Content Provider с правами доступа.

WARNING: Hardcoded Secrets

Severity: WARNING
CWE: CWE-798 (Use of Hard-coded Credentials)

Найдено:

"google_api_key":"AIzaSyCKvlAvtCaEuj0WuF1gxesJv_j6hHuoEHo"
"facebook_client_token":"c5a29925ae6d41fe68136a6edfc5749f"
"firebase_database_url":"https://td-project-01.firebaseio.com"

Риск:

  • API-ключи извлечены из APK
  • Злоумышленник может использовать ключи
  • Квоты и лимиты могут быть исчерпаны

Митигация:

  • Вынести ключи в переменные окружения или BuildConfig
  • Использовать backend-прокси для доступа к внешним API
  • Регулярно ротировать ключи

WARNING: Небезопасный генератор случайных чисел

Severity: WARNING
CWE: CWE-330 (Use of Insufficiently Random Values)

Описание: Используется java.util.Random вместо java.security.SecureRandom.

Риск:

  • Предсказуемые значения
  • Компрометация токенов, ключей, nonce

Митигация:

// НЕБЕЗОПАСНО:
Random random = new Random();

// БЕЗОПАСНО:
SecureRandom random = new SecureRandom();

WARNING: Слабые хеш-функции

Severity: WARNING
CWE: CWE-328

Найдено:

  • Использование MD5 (известны коллизии)
  • Использование SHA-1 (известны коллизии)

Митигация:

  • Заменить на SHA-256 или SHA-3
  • Для паролей использовать bcrypt, scrypt или Argon2

WARNING: Запись чувствительных данных в логи

Severity: WARNING
CWE: CWE-532 (Insertion of Sensitive Information into Log File)

Описание: В логах могут попадать чувствительные данные (токены, идентификаторы пользователей).

Митигация:

  • Отключить логирование в production-сборках
  • Использовать ProGuard/R8 для удаления логов
  • Применять фильтры для маскирования чувствительных данных

Проблема: Файлы доступны для записи любому приложению

Действия:

  1. Найти все места создания SharedPreferences
  2. Заменить MODE_WORLD_WRABLE на MODE_PRIVATE

  4. Протестировать функциональность

  3. Настроить backend-прокси для чувствительных операций
  4. Отозвать скомпрометированные ключи
  5. Сгенерировать новые

Ответственный: Backend Developer + DevOps
