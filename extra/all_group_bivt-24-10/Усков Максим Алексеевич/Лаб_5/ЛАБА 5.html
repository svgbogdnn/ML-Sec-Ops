ЛАБА 5. Базовая настройка безопасности Docker-контейнера

Цель

Закрепить на практике материал с лекции и научиться на базовом уровне обеспечивать безопасность Docker-контейнеров.

В работе используется образ из Docker Hub:

nginx:1.27-alpine

Я выбрал его потому что это небольшой популярный образ на базе Alpine Linux, у него есть командная оболочка sh, и на нем удобно показать запуск контейнера от обычного пользователя.

Часть I

Команды

Сначала скачиваю образ:

docker pull nginx:1.27-alpine

Смотрю список образов на машине:

docker image ls

До запуска контейнера проверяю пользователя на хосте:

whoami

В моем случае пользователь на хосте:

qquerell

Запускаю sh внутри контейнера:

docker run --rm -it nginx:1.27-alpine sh

Внутри контейнера выполняю:

whoami

Ожидаемый результат:

root

Вывод по части I

По умолчанию контейнер запускается от пользователя root. Это небезопасно, потому что при эксплуатации уязвимости внутри приложения атакующий получает root-права внутри контейнера. Контейнерная изоляция снижает риск, но не делает такой запуск безопасным.

Часть II

Dockerfile

Файл лежит здесь:

~/programming/misis/IS/lab5/Dockerfile

Содержимое Dockerfile:

FROM nginx:1.27-alpine



RUN addgroup -S appgroup \

    && adduser -S -D -H -u 10001 -G appgroup appuser \

    && mkdir -p /var/cache/nginx /var/run /var/log/nginx /tmp \

    && chown -R appuser:appgroup /var/cache/nginx /var/run /var/log/nginx /tmp /usr/share/nginx/html \

    && sed -i 's/listen       80;/listen       8080;/' /etc/nginx/conf.d/default.conf \

    && sed -i 's/listen  \[::\]:80;/listen  [::]:8080;/' /etc/nginx/conf.d/default.conf \

    && sed -i '/^user /d' /etc/nginx/nginx.conf \

    && sed -i 's|pid        /var/run/nginx.pid;|pid        /tmp/nginx.pid;|' /etc/nginx/nginx.conf



EXPOSE 8080



USER appuser



HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD wget -qO- http://127.0.0.1:8080/ >/dev/null || exit 1



CMD ["nginx", "-g", "daemon off;"]



# Дополнительные настройки безопасности:

# 1. В Dockerfile:

#    - запуск процесса через USER appuser, а не от root;

#    - фиксированный тег базового образа вместо latest;

#    - минимальный alpine-образ;

#    - отсутствие секретов, паролей и токенов в слоях образа;

#    - EXPOSE только нужного порта 8080 вместо привилегированного 80.

# 2. При запуске контейнера:

#    docker run --rm -p 8080:8080 \

#      --read-only \

#      --tmpfs /tmp:rw,noexec,nosuid,size=64m \

#      --tmpfs /var/cache/nginx:rw,noexec,nosuid,size=64m \

#      --tmpfs /var/run:rw,noexec,nosuid,size=16m \

#      --cap-drop=ALL \

#      --security-opt no-new-privileges \

#      --pids-limit=128 \

#      --memory=256m \

#      --cpus=0.5 \

#      lab5-nginx-secure

# 3. Если сеть контейнеру не нужна, можно добавить флаг --network=none.

Сборка образа

cd ~/programming/misis/IS/lab5

docker build -t lab5-nginx-secure .

Проверка пользователя внутри контейнера

docker run --rm -it lab5-nginx-secure sh

whoami

Ожидаемый результат:

appuser

Вывод по части II

В Dockerfile добавлен непривилегированный пользователь appuser, и контейнер запускается через инструкцию:

USER appuser

Также nginx перенесен с порта 80 на 8080, потому что порт 80 является привилегированным. Для дополнительного усиления безопасности в комментариях к Dockerfile указаны флаги запуска: --read-only, --cap-drop=ALL, --security-opt no-new-privileges, ограничения CPU/RAM/PID и tmpfs для временных файлов.

Часть III

Для сканирования использую Trivy.

Так как локально Trivy не был установлен, я запустил его как Docker-контейнер:

docker run --rm \

  -v /var/run/docker.sock:/var/run/docker.sock \

  aquasec/trivy:latest image lab5-nginx-secure

Анализ результата

Сканер проверяет пакеты внутри образа и показывает найденные CVE с уровнем опасности: LOW, MEDIUM, HIGH, CRITICAL.

По результату сканирования образа lab5-nginx-secure найдено:

Total: 90

UNKNOWN: 0

LOW: 27

MEDIUM: 39

HIGH: 22

CRITICAL: 2

Главное в этом результате - наличие HIGH и CRITICAL уязвимостей. Такие уязвимости нужно разбирать в первую очередь: смотреть, для каких пакетов они найдены, есть ли исправленная версия в колонке FIXED VERSION, и можно ли обновить базовый образ.

Вывод по части III

Образ lab5-nginx-secure был проверен сканером Trivy. Сканер нашел 90 уязвимостей: 27 LOW, 39 MEDIUM, 22 HIGH и 2 CRITICAL.

Наличие HIGH и CRITICAL уязвимостей говорит о том, что образ нельзя считать полностью безопасным. В первую очередь нужно обновить базовый образ nginx:1.27-alpine до более новой версии, пересобрать контейнер и повторить сканирование. Также нужно смотреть колонку FIXED VERSION: если исправленная версия пакета доступна, пакет или базовый образ нужно обновить.

При этом запуск контейнера от непривилегированного пользователя appuser снижает риск эксплуатации, но не устраняет уязвимости внутри системных пакетов образа.
