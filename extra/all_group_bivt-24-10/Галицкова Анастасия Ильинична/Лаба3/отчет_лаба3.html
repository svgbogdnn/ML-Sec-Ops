Часть II. Практическая симуляция

1. Развертывание стенда

docker pull ket9/otus-devsecops-xss
docker run -d -p 8080:80 ket9/otus-devsecops-xss:latest

После запуска приложение доступно по адресу: http://localhost:8080

2. Ход рассуждений и тестирование

Шаг 1. Первичный осмотр

На главной странице обнаружена форма с текстовым полем ввода. При вводе обычного текста (test123) он отображается на той же странице после отправки.

Шаг 2. Проверка на обработку HTML

Ввожу тестовый HTML-тег:

<h1>Hello</h1>

Результат: Браузер отобразил текст как заголовок (крупным жирным шрифтом). Это означает, что теги не экранируются и интерпретируются браузером.

Шаг 3. Попытка выполнения JavaScript

Пробую классический payload:

<script>alert('XSS')</script>

Результат: Окно не появилось. Скорее всего, сервер удаляет или экранирует тег <script>.

Шаг 4. Обход фильтрации

Использую тег <img> с обработчиком события onerror:

<img src="invalid.jpg" onerror="alert('XSS_OTUS')">

Результат: Появилось всплывающее окно alert('XSS_OTUS'). Атака успешна.

✅ Доказательство выполнения JS-скрипта

При вводе payload <img src="invalid.jpg" onerror="alert('XSS_OTUS')"> в уязвимое поле:

  1. Браузер пытается загрузить изображение по пути invalid.jpg
  2. Загрузка не удается (404 или отсутствует файл)
  3. Срабатывает событие onerror
  4. Выполняется JavaScript-код alert('XSS_OTUS')
  5. На экране появляется модальное окно с текстом

📌 Тип найденной уязвимости

Reflected XSS (Отраженная межсайтовая скриптовая уязвимость)

Обоснование:

  • Зловредный код не сохраняется на сервере (в базу данных или файлы)
  • Код отражается (возвращается) в теле HTTP-ответа немедленно после отправки запроса
  • Для успешной атаки жертву необходимо обманом заставить перейти по специально сформированной ссылке

Вектор атаки:

http://localhost:8080/?search=<img src=x onerror=alert('XSS')>

Часть III. Меры предотвращения

1. Экранирование вывода (главная защита)

При выводе любых пользовательских данных в HTML-коде необходимо заменять спецсимволы на HTML-сущности.

Какие символы нужно экранировать:

Символ HTML-сущность
& &amp;
< &lt;
> &gt;
" &quot;
' &#039; (или &apos;)

Реализация на PHP:

// Уязвимый код (НЕ ДЕЛАТЬ ТАК)
echo $_GET['search'];

// Безопасный код
$safe_input = htmlspecialchars($_GET['search'], ENT_QUOTES | ENT_HTML5, 'UTF-8');
echo $safe_input;

Что делает ENT_QUOTES: экранирует и двойные, и одинарные кавычки. Это закрывает векторы атаки через атрибуты тегов (например, value='...').

2. Защита на уровне HTTP-заголовков

// Content-Security-Policy — запрет inline-скриптов и скриптов с внешних доменов
header("Content-Security-Policy: default-src 'self'; script-src 'self'");

// X-XSS-Protection — для старых версий браузеров
header("X-XSS-Protection: 1; mode=block");

// HttpOnly для Cookie — защита сессии от кражи через document.cookie
session_set_cookie_params(['httponly' => true]);
