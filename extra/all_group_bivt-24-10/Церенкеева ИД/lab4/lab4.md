# Часть 1

## фрагмент кода 1
недостаток: secret key хранится в исходном коде.
зная secret key модно подделывать сессии пользователей, создавать произвольные cookie и получать доступ к админке или данным др пользователей.
решение: ключ должен браться из переменных окружения или отдельного конфигурационного файла, который не попадает в систему контроля env и gitignore

## фрагмент кода 2
недостаток: 
используется устаревший класс TextField. 
вместо него нужно использовать StringField.
старые классы могут не поддерживать новые проверки безопасности и фильтры. 
это может привести к тому, что вредоносные данные пройдут проверку формы
решение:
заменить TextField на StringField. 
добавить валидаторы , чтобы сервер проверял, что пользователь ввел данные правильного формата и длины.

## фрагмент кода 3
недостаток: неправильная обработка ошибок. 
в блоке except программа ловит любую ошибку, но не показывает сообщения о проблеме.
показывает страницу «Успешно создано». также ошибка нигде не записывается в логи.
решение: нужно разделять типы ошибок
если данные неверные то показать пользователю сообщение об ошибке
если случ критическая поломка то записать ее в лог админа, а пользователю вывести сообщение об ошибке 


# Часть 2

Атаки:
- SQL-инъекции
база данных получает запросы так, что текст пользователя не может изменить команду sql.
-XSS
все, что выводится на экран, автоматически очищается от опасных символов, чтобы чужой код не выполнился в другому браузере
-CSRF
для любых действий требуется специальный токен, который злоумышленник не может подделать
-Кликджекинг
сайт запрещает открывать себя внутри фреймов на других страницах, чтобы нельзя было скрытно заставить пользователя нажать кнопку.

когда пользователь заходит на сайт, сервер создает для него уникальную запись с данными и сохраняет её у себя в бд.
сервер дает пользователю только номер этой записи, который хранится в куках браузера. 
этот номер подписан секретным ключом, поэтому его нельзя подделать.
при каждом новом запросе браузер отправляет этот номер обратно. 
сервер смотрит по номеру, кто это, и загружает данные пользователя.
если пользователь выходит из системы, сервер просто удаляет эту запись, и номер становится недействительным
так как сами данные лежат на сервере, а не у клиента
