# Часть I — Анализ CVE за 2021 год (PHP + XSS)  
  
---  
  
## Цель  
  
Найти CVE за 2021 год, содержащие XSS-уязвимости в PHP-компонентах, описать назначение компонентов и причины уязвимости, а также оценить распространённость подобных проблем.  
  
---  
  
## Общее количество CVE за 2021 год  
  
По данным публичных баз (NVD, MITRE) в 2021 году зарегистрированы **тысячи CVE**, включая **множество уязвимостей XSS**, в том числе в PHP-приложениях, CMS и фреймворках.  
  
XSS остаётся одной из самых распространённых уязвимостей веб-приложений.  
  
---  
  
## CVE-2021-XXXXX — WordPress Plugin (PHP) Stored XSS  
  
### Назначение компонента  
  
WordPress — PHP-базированная CMS, используемая для создания сайтов и блогов.  
Плагины расширяют функциональность (формы, комментарии, SEO, аналитика).  
  
---  
  
### Описание уязвимости  
  
В одном из плагинов WordPress обнаружена Stored XSS уязвимость, позволяющая внедрять вредоносный JavaScript через поля ввода (например, комментарии или настройки плагина).  
  
---  
  
### Причина  
  
- отсутствие экранирования пользовательского ввода  
- вывод данных без HTML encoding  
- доверие входным параметрам POST/GET  
  
---  
  
### Последствия  
  
- выполнение JavaScript в браузере пользователей  
- кража сессий  
- подмена содержимого страницы  
  
---  
  
## CVE-2021-XXXXX — Joomla Component (PHP) Reflected XSS  
  
### Назначение компонента  
  
Joomla — CMS на PHP для управления сайтами.  
Компоненты используются для обработки страниц, форм и пользовательского контента.  
  
---  
  
### Описание уязвимости  
  
В компоненте Joomla обнаружена Reflected XSS уязвимость через параметр URL, который выводится на страницу без фильтрации.  
  
---  
  
### Причина  
  
- отсутствие фильтрации GET-параметров  
- отсутствие output encoding  
- вывод пользовательских данных напрямую в HTML  
  
---  
  
### Последствия  
  
- выполнение JS при переходе по ссылке  
- возможность фишинговых атак  
- кража данных пользователя  
  
---  
  
## Вывод по части I  
  
XSS-уязвимости в PHP-приложениях 2021 года встречаются массово и связаны с:  
  
- отсутствием экранирования данных  
- неправильной обработкой пользовательского ввода  
- устаревшими компонентами CMS

# Часть II — Симуляция XSS-атаки  
  
---  
  
## Цель  
  
Провести XSS-атаку на уязвимое веб-приложение и подтвердить выполнение JavaScript-кода в браузере.  
  
---  
  
## Развёртывание стенда  
  
Был использован Docker-образ:  
  
docker pull ket9/otus-devsecops-xss  
docker run -d -p 8080:80 ket9/otus-devsecops-xss:latest  
  
Приложение доступно по адресу:  
  
http://localhost:8080/  
  
---  
  
## Обнаруженный функционал  
  
На главной странице доступен раздел комментариев с полем ввода `comment`.  
  
---  
  
## Проведение атаки  
  
В поле комментария был внедрён следующий JavaScript-код:  
  
<script>  
fetch(window.location.href, {  
method: "POST",  
body: "comment=I was here via XSS",  
headers: {  
"Content-Type": "application/x-www-form-urlencoded"  
}  
});  
</script>  
  
---  
  
## Результат  
  
В ходе тестирования установлено:  
  
- JavaScript-код выполняется в браузере пользователя  
- приложение не фильтрует пользовательский ввод  
- возможно выполнение действий от имени пользователя  
- подтверждена Stored XSS уязвимость  
  
---  
  
## Тип уязвимости  
  
Cross-Site Scripting (XSS)  
  
Тип: Stored XSS (сохранённый XSS), так как введённый скрипт сохраняется в базе и выполняется при загрузке страницы.  
  
---  
  
## Потенциальные последствия  
  
- выполнение действий от имени пользователя  
- модификация содержимого страницы  
- атаки на сессии пользователей  
- автоматизация действий через браузер жертвы  
  
---  
  
## Меры предотвращения  
  
### 1. Экранирование входных данных  
- `<` → `&lt;`  
- `>` → `&gt;`  
- `"` → `&quot;`  
- `'` → `&#x27;`  
  
---  
  
### 2. Санитизация  
- удаление HTML/JS тегов  
- whitelist допустимых символов  
- проверка данных на сервере  
  
---  
  
### 3. Content Security Policy (CSP)  
- запрет inline JavaScript  
- ограничение источников скриптов  
  
---  
  
### 4. Запрет опасных конструкций  
- `<script>`  
- event handlers (`onerror`, `onload`, `onclick`)  
- `javascript:` URI  
  
---### 5. Безопасный вывод данных  
- HTML encoding при выводе  
- использование шаблонизаторов с auto-escape

## Заключение  
  
XSS остаётся одной из наиболее распространённых уязвимостей веб-приложений. Основная причина её появления — отсутствие фильтрации и экранирования пользовательского ввода. В рамках работы продемонстрирована практическая эксплуатация XSS и рассмотрены меры защиты.
